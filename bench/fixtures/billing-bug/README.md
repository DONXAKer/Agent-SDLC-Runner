# billing-bug

Выставление счетов за товары: позиции со скидкой, подытог, доставка, скидка счёта, итог.

## Как устроено

| Модуль | Отвечает за |
|---|---|
| `src/money.ts` | Деньги. Всё считается в **копейках** целым числом. Процент округляется **половиной вверх** — правило одно на весь расчёт, своего округления в других модулях не заводится. |
| `src/lines.ts` | Позиции счёта: количество × цена, скидка позиции, подытог. |
| `src/invoice.ts` | Сборка счёта: подытог → доставка → скидка счёта → итог. |
| `src/index.ts` | Публичный контракт: снаружи вызывают только его. |

## Правила расчёта

- Стоимость позиции — количество × цена единицы. Скидка позиции (`discountPct`) считается
  **от стоимости всей строки** одним процентом: `qty × price`, от неё — процент, разность.
  Округление — общее правило пакета, половина вверх, один раз на строку.
- Подытог счёта — сумма стоимостей позиций.
- Скидка счёта (`discountPct`) — **от стоимости товаров**, то есть от подытога. Доставка
  **не дисконтируется**: её оплачивают целиком при любой скидке.
- Итог — подытог плюс доставка минус скидка. Итог **не бывает отрицательным**.

## Единицы и соглашения

- Деньги — копейки, целое число. `rub(249)` → `24900`.
- Порядок расчёта закреплён: позиции → подытог → доставка → скидка → итог.
- Форма `Invoice` — контракт: её сверяют литералом в тестах.

## Как запускать

```bash
node scripts/build-check.mjs      # «сборка»: загрузка всех модулей src
node --test "test/**/*.test.ts"   # тесты
```

Компиляции нет: TypeScript исполняется напрямую, типы снимает Node (нужен 23.6 или новее).
Зависимостей у пакета нет, `npm install` не требуется.
