# notify

Отправка уведомлений через инъектируемый транспорт. Сети здесь нет: транспорт — интерфейс,
в тестах — памятный (`memoryTransport`), и всё, что уходит «наружу», можно прочитать из
его `sent`.

## Как устроено

| Модуль | Отвечает за |
|---|---|
| `src/message.ts` | Форма уведомления `OutMessage`: email-адресат (`to`), текст, необязательный телефон. `to` и `phone` — персональные данные. |
| `src/transport.ts` | Интерфейс `Transport` и памятный `memoryTransport()` — стенд для тестов. Транспорт доставляет и выдаёт id отправки; о содержимом он не рассуждает. |
| `src/sender.ts` | `sendNotification(transport, msg)` — точка отправки одного уведомления. Тонкая обёртка: сюда встают правила отправки, когда появятся. |
| `src/outbox.ts` | Очередь исходящих: `createOutbox()` → `enqueue` накапливает, `drain(transport)` отправляет накопленное. |
| `src/log.ts` | Журнал событий в памяти: `logEvent`, `events`, `resetLog`. |
| `src/index.ts` | Публичный контракт: снаружи вызывают только его. |

## Соглашения

- Транспорт возвращает id отправки строкой; что это за id — дело транспорта, отправитель
  его только пробрасывает.
- Очередь отдаёт уведомления в порядке постановки: `drain` — это «отправить всё, что
  накопилось», а не планировщик.
- **В журнал персональные данные не пишутся — это политика, а не случайность.** Адресат,
  телефон и текст уведомления в `logEvent` не попадают ни целиком, ни частями: журнал
  читают люди, у которых нет права видеть, кому и что мы отправили. Записываются события и
  счётчики — «отправлено из очереди: 3», а не «отправлено ivan@example.ru».

## Как запускать

```bash
node scripts/build-check.mjs      # «сборка»: загрузка всех модулей src
node --test "test/**/*.test.ts"   # тесты
```

Компиляции нет: TypeScript исполняется напрямую, типы снимает Node (нужен 23.6 или новее).
Зависимостей у пакета нет, `npm install` не требуется.
