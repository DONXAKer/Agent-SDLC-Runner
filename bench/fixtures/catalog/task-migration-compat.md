# Ставка НДС в записи каталога

Ставка НДС у товаров разная, а в каталоге её нет: выгрузка в бухгалтерию считает всё по одной
ставке и раз в квартал это вылезает расхождением. Ставку записываем в каталог.

## Что должно получиться

1. `Product` (`src/product.ts`) получает поле `vatRate: number` — ставка НДС товара в
   процентах. Конструктор `product()` принимает её четвёртым, **необязательным**
   параметром.
2. Новые записи пишутся с полем: `serialize` (`src/store.ts`) добавляет `vatRate` в строку
   после `priceK`.
3. Старые файлы (без поля) обязаны читаться: `parse` для строки без `vatRate` подставляет
   ставку **по умолчанию**. Её значение в репозитории не записано. Явная ставка в записи
   побеждает умолчание — оно подставляется только там, где поля нет.
4. Умолчание одно на оба входа — и для `product()` без четвёртого параметра, и для старой
   строки файла: константа одна. Иначе запись, собранная конструктором, после
   `parse(serialize(p))` разойдётся сама с собой.
5. Существующие тесты остаются зелёными и **без правки**, набор прогнан по-настоящему
   командой проекта. В журнал этапа идёт то, что напечатала команда.

## Рамки

- Ветка витка заведена: `sdlc/migration-compat`. Виток полный — мелким контуром не закрывать.
- README в этом витке не трогаем: таблицу формата обновляет владелец формата вместе с
  внешними службами, отдельным витком. Каталог `test/` тоже не трогаем — тесты миграции
  придут вместе с фикстурами реальных старых файлов.
- Артикул, название и цена не меняются; формат файла (JSONL, строка на запись) — тоже.
