# Срок оплаты по умолчанию

У счёта нет срока оплаты: покупатель трактует его как «когда-нибудь». Нужен срок, заданный
конфигом площадки.

## Что должно получиться

1. `BillingConfig` (`src/config.ts`) получает опцию `defaultDueDays` — срок оплаты в днях
   по умолчанию. Встроенный дефолт (когда и площадка молчит) — **14**.
2. `Invoice` получает поле `dueDays: number` — всегда, у любого счёта. Источник значения по
   приоритету: явная опция при вызове → конфиг площадки → встроенные 14. Опции вызова
   передаются пятым параметром-объектом: `bill(number, customer, lines, config?, opts?)`,
   где `opts.dueDays?: number`.
3. Таблица опций в разделе «Конфигурация» `README.md` дополняется строкой про
   `defaultDueDays` — конфиг, не задокументированный рядом с типом, находят по второму
   разу.
4. Все места, где читается конфиг, остаются согласованными: чтение по-прежнему идёт через
   `resolveConfig`, прямых обращений к `DEFAULT_CONFIG` не появляется.
5. На новое поведение есть тест рядом с существующими (`test/`), набор прогнан по-настоящему
   командой проекта; в журнал этапа идёт то, что напечатала команда. Существующие тесты
   без правки и зелёные — с одним исключением: тест формы счёта «ровно пять полей» в
   `test/invoice.test.ts` обновляется под новое обязательное поле (шесть полей), других
   правок существующих тестов нет.

## Рамки

- Ветка витка заведена: `sdlc/config-default`. Виток полный — мелким контуром не закрывать.
- Опция — про срок оплаты, а не про форму счёта в целом: остальные поля `Invoice` не
  меняются.
