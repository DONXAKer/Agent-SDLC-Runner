# warehouse

Складские лимиты хранения по категориям товара и пересчёт веса объёмных товаров для
тарификации места.

## Как устроено

| Модуль | Отвечает за |
|---|---|
| `src/limits.ts` | Лимит хранения по категории: `CATEGORY_LIMIT` и `limitFor`. Ступень лимита **одна**: для категории есть ровно одно число либо нет лимита вовсе (`null`) — ни второй ступени, ни повышенного лимита «сверх базового» в модели нет. Неизвестная категория даёт `null`, а не молчаливый дефолт. |
| `src/coef.ts` | Коэффициенты пересчёта: `FRAGILITY_FACTOR` (хрупкое занимает больше места) и `volumetricWeightG` — объёмный вес по габаритам, в граммах, вверх до 100 г. |
| `src/index.ts` | Публичный контракт: снаружи вызывают только его. |

## Единицы и соглашения

- Лимиты — штуки на ячейку хранения, целое число.
- Вес — граммы, целое число. Объёмный вес округляется **вверх** до 100 г: место на полке
  занимается целыми ячейками, и недобор оплачивает склад, а не клиент.
- Габариты — сантиметры, тройка `[длина, ширина, высота]`. Порядок сторон не нормализован:
  приёмка вводит их так, как удобно мерить; для произведения он и не важен.
- Ступень лимита одна; коэффициент упаковки не зафиксирован в коде — уточнять у приёмки.

## Как запускать

```bash
node scripts/build-check.mjs      # «сборка»: загрузка всех модулей src
node --test "test/**/*.test.ts"   # тесты
```

Компиляции нет: TypeScript исполняется напрямую, типы снимает Node (нужен 23.6 или новее).
Зависимостей у пакета нет, `npm install` не требуется.
