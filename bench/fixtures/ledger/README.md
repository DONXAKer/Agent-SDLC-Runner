# ledger

Складской учёт: остатки по складам, резервы под заказы, отчёт для сверки с инвентаризацией.
Денег здесь нет — количества в штуках.

## Как устроено

| Модуль | Отвечает за |
|---|---|
| `src/stock.ts` | Таблица остатков `STOCK_TABLE` (склад → строки `{ sku, qty }`) — источник истины инвентаризации, заполнена вручную по актам пересчёта. Поиск `findEntry`, раскладка по складам `stockOf`, сумма по набору `totalQty`. |
| `src/keys.ts` | Ключ записи «склад + позиция» — `keyFor`. Шаблон один на весь пакет: по этому ключу хранятся резервы. |
| `src/reserve.ts` | Резерв под заказ: `reserve` и таблица действующих резервов `RESERVED` по ключу из `keys.ts`. |
| `src/report.ts` | Отчёт по складу `stockReport` — срез таблицы для сверки с актом. |
| `src/index.ts` | Публичный контракт: снаружи вызывают только его. Там же фасад `api`. |

## Договорённости

- **Дубликаты sku: действует первая запись.** В таблице есть позиции, заведённые на одном
  складе дважды двумя приходами; так считала инвентаризация, и поиск, отчёт и резерв обязаны
  отвечать по первой записи. Каждый дубликат помечен комментарием у строки.
- **Резерв: остатка впритык хватает.** Граница включающая — резерв на ровно весь остаток
  ставится, на единицу больше — нет.
- **Резерв на позицию один.** Пока действующий резерв не снят, второй не ставится; поэтому
  из остатка резерв не вычитается.
- Коды позиций в таблице — в верхнем регистре с дефисом (`AZ-123`), как печатает этикетку
  приёмка. Коды складов — `wh-msk`, `wh-spb`, `wh-ekb`, `wh-vld`.
- Ключ записи собирается только через `keyFor`; литералы вида `'wh-msk#AZ-123'` в коде не
  пишутся.

## Как запускать

```bash
node scripts/build-check.mjs      # «сборка»: загрузка всех модулей src
node --test "test/**/*.test.ts"   # тесты
```

Компиляции нет: TypeScript исполняется напрямую, типы снимает Node (нужен 23.6 или новее).
Зависимостей у пакета нет, `npm install` не требуется.
