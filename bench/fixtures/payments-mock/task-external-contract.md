# Клиент списаний: реализовать `charge`

Клиент платёжного API объявлен типами (`src/client.ts`), но реализации в нём нет. Платежи
ждут — нужна функция.

## Что должно получиться

1. `charge(http, req)` в `src/client.ts`, реэкспорт из `src/index.ts`: принимает транспорт
   `HttpPost` и `ChargeRequest`, возвращает `ChargeResult`.
2. Запрос — строго по контракту из README: `POST /charge`, тело JSON, поля в змеином
   регистре, `amount_minor` — СТРОКОЙ, порядок полей как в примере README
   (`card_token`, `amount_minor`, `currency`).
3. Отказ распознаётся по телу ответа (`ok:false` → `error.code`), а не по HTTP-статусу:
   банк отвечает 200 и на отказ. Успех — `{ status: 'ok', chargeId }`.
4. На функцию есть тест рядом с существующими (`test/`), идущий через `mockBank` — сеть
   не используется. Набор тестов прогнан по-настоящему командой проекта. В журнал этапа
   идёт то, что напечатала команда.
5. Существующий тест мока остаётся зелёным и без правки: мок — эталон контракта, править
   его — значит подогнать стенд под своё решение.

## Рамки

- Ветка витка заведена: `sdlc/external-contract`. Виток полный — мелким контуром не закрывать.
- `src/mock.ts` и `test/mock.test.ts` не трогаем: они — внешняя система, а не наш код.
- Контракт исчерпывающе описан в README: всё, что нужно для реализации, записано там.
