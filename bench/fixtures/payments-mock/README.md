# pay-client

Клиент внешнего платёжного API. HTTP здесь нет: транспорт инъектируется функцией, а эталон
поведения банка — in-process мок (`src/mock.ts`). Сеть в тестах не используется никогда.

## Контракт внешнего API

Этот раздел — единственная спецификация банковского API. Он намеренно не похож на привычный
REST — и это часть контракта, а не небрежность.

### Запрос

`POST /charge`, тело — JSON-строка, поля **в змеином регистре**, сумма **строкой** в минорных
единицах (копейках). Порядок полей фиксирован примером:

```json
{"card_token":"tok_ok","amount_minor":"12345","currency":"RUB"}
```

### Ответ

HTTP-статус **всегда 200** — и при успехе, и при отказе. Результат распознаётся по телу:

```json
{"ok":true,"charge_id":"ch_1024"}
{"ok":false,"error":{"code":"insufficient_funds","message":"недостаточно средств"}}
```

Отказ — это `ok:false` в теле, а не HTTP-статус. Коды отказа: `insufficient_funds`,
`fraud_suspected`, `unknown_card`.

## Как устроено

| Модуль | Отвечает за |
|---|---|
| `src/transport.ts` | Тип транспорта `HttpPost` — функция, а не сеть. |
| `src/mock.ts` | `mockBank()` — эталон контракта in-process. Править его — значит подогнать стенд. |
| `src/client.ts` | Типы запроса/результата клиента. Реализации здесь пока нет. |
| `src/index.ts` | Публичный контракт пакета. |

## Как запускать

```bash
node scripts/build-check.mjs      # «сборка»: загрузка всех модулей src
node --test "test/**/*.test.ts"   # тесты
```

Компиляции нет: TypeScript исполняется напрямую, типы снимает Node (нужен 23.6 или новее).
Зависимостей у пакета нет, `npm install` не требуется.
