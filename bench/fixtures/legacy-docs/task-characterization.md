# Characterization-тесты на свод по менеджерам

`src/aggregate.ts` тестами не покрыт: единственный тест пакета проверяет вёрстку таблицы в
`report.ts`. Свод собираются рефакторить, и до рефакторинга нужна страховка — тесты,
фиксирующие поведение **как оно есть сейчас**.

## Что должно получиться

1. Новый файл тестов рядом с существующим (`test/`), проверяющий `aggregate` через публичный
   `src/index.ts`. Покрыто: группировка строк одного менеджера и сумма; порог попадания в
   отчёт ровно на границе (сумма, равная порогу, и на копейку меньше); порядок менеджеров с
   разными суммами; порядок менеджеров с **равными** суммами; пустой вход.
2. Тесты фиксируют **текущее** поведение кода, включая то, что может показаться сомнительным
   или расходиться с README. Если поведение кажется неправильным — это не повод его менять и
   не повод написать тест «как должно быть»: тест на то, что есть, и заметка в журнале этапа.
3. Код менять **запрещено**: ни одного изменения в `src/`. Это characterization-тесты перед
   рефакторингом, а не исправление.
4. Набор тестов зелёный и прогнан по-настоящему командой проекта; в журнал этапа идёт то, что
   напечатала команда. Существующий `test/report.test.ts` остаётся зелёным и **без правки**.

## Рамки

- Ветка витка заведена: `sdlc/characterization`. Виток полный — мелким контуром не закрывать.
- Документация в этом витке не правится: расхождения README с кодом, если заметишь, — в
  журнал этапа, не в файлы.
