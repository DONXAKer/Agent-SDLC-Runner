# Документация отчёта отстала от кода

Код свода (`src/aggregate.ts`) менялся не один раз, а README и комментарии в нём — нет.
Сегодня тот, кто читает документацию, узнаёт про отчёт не то, что делает программа. Задача —
про документацию: истина здесь в коде, а не в тексте.

## Что должно получиться

1. Раздел «Правила отчёта» в `README.md` описывает то, что код `aggregate.ts` делает
   **сегодня**: в каком порядке идут менеджеры, какой порог попадания в отчёт и включает
   ли он границу, что происходит при равных суммах. Каждое утверждение раздела сверено с
   кодом, а не с прежним текстом.
2. Комментарии в `src/aggregate.ts` (шапка файла, docstring'и константы и функции) не
   противоречат коду, который они описывают. Правятся **только комментарии**: ни один
   исполняемый символ файла не меняется — ни порядок сортировки, ни порог, ни форма
   результата.
3. Документация описывает текущее поведение, а не историю: пометки вида «раньше было так,
   теперь иначе» и «устарело» не нужны — прежней формулировки в тексте не остаётся.
4. Существующие тесты остаются зелёными и **без правки**; набор прогнан командой проекта, в
   журнал этапа идёт то, что напечатала команда.

## Рамки

- Ветка витка заведена: `sdlc/docs-sync`. Виток полный — мелким контуром не закрывать.
- Код в `src/` не трогаем: исполняемые строки не меняются ни в одном файле. Единственная
  допустимая правка внутри `src/` — текст комментариев в `aggregate.ts`.
- Поведение отчёта менять нельзя, даже если оно кажется странным: задача про документацию.
