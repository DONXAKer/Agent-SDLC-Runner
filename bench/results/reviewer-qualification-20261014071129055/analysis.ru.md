# Qwen 27B: новые задачи для рецензента

Результат: 13/16 верных суждений; 6/8 задач правильно оценены в обоих порядках.
Ошибочный патч не выбран ни в одном валидном ответе. Два ответа противоречивы
(отказ одновременно с непустым selected); ещё один — ложный reject_all при
наличии корректного кандидата. Невалидные ответы считаются ошибками, их
содержание не исправлялось и в число валидных выборов не включалось.

| Случай | Прямой порядок | Обратный порядок |
|---|---|---|
| Граница срока действия кеша | Верно | Верно |
| Нулевая настройка и зависимый потребитель | Противоречивый ответ | Верно |
| Новый экспорт и совместимость старого | Противоречивый ответ | Ложный отказ |
| Только собственные свойства объекта | Верно | Верно |
| Значения null/false/0/пустая строка | Верно | Верно |
| Синхронный callback ровно один раз | Верно | Верно |
| Неизвестный контракт отсутствующего helper | Верно | Верно |
| Неизвестные единицы пагинации сервиса | Верно | Верно |

Время всех вызовов: 165,63 с, включая возможную загрузку модели.
Модель: `ollama:qwen3.8-27b-iq4-gpumax`. Тот же общий системный промпт и
лимит ответа 1024 токена, что в первом screening-прогоне; промпт не
подстраивался под новые задачи или ответы. Проверялись готовые тексты:
рабочий код не менялся и решения не применялись.

Все три сбоя относятся к двум задачам с несколькими файлами. В задаче нового
экспорта правильный кандидат сохраняет `parse` как alias `decode`, а приложение
переходит на `decode`. Контрольные проверки проходят. В прямом порядке судья
правильно описал это, но выдал reject_all вместе с selected. В обратном порядке
он сначала заявил, что экспорт отсутствует, затем сам обнаружил его сохранение,
однако итогом остался отказ. Текст обоснования заканчивается незавершённой
мыслью внутри валидного JSON. Сбой нельзя свести только к форме ответа.

Предыдущий screening дал 14/16 на других задачах. Результаты не объединены:
новый набор отличается сложностью и форматом источников. Строгий валидатор
прежний; две противоречивые комбинации outcome/selected им отклонены.

Вывод: оставить Qwen кандидатом для советующего режима; для блокирующего
арбитра оснований недостаточно. Следующий полезный эксперимент — разделить
проверку каждого патча и итоговое ранжирование, чтобы независимо измерить
качество содержательной оценки и согласованность решения. Проверять новый
протокол следует также на следующем заранее размеченном наборе, сохраняя
этот набор как регрессионный. Автоматический shadow-режим основного цикла
данным экспериментом не реализован и профили не включались.

## Воспроизведение и пределы

`node tools/reviewer-qualification.ts --fixtures bench/experiments/reviewer-holdout-v1.json --model ollama:qwen3.8-27b-iq4-gpumax --run`

Восемь новых авторских задач JavaScript/CommonJS, по два порядка кандидатов.
Это отложенный набор относительно первого screening, но не независимый
внешний holdout, не полный SDLC-прогон и не измерение производственных дефектов.
Один ответ на каждый порядок не отделяет влияние позиции от случайности
генерации. Нулевая частота ошибочных выборов здесь не доказывает безопасность.

Ожидаемые ответы зафиксированы до вызовов модели. Для шести определённых
задач метки проверены выполнением JavaScript в Node vm; исключение в коде
кандидата считается провалом проверки и отдельно записывается. Два случая
с неизвестными контрактами размечены по явно недостающим исходным данным.
Модель не видела меток и контрольных проверок. Модули фикстур загружаются
из явной карты исходников без доступа к модулям хоста; поддержка произвольных
языков и систем модулей не заявляется.

`suite.json` содержит хэши fixture и harness, результаты проверки меток,
параметры, usage, времена и решения. Полные запросы/ответы находятся рядом.
Хэш fixture: `d58af119184c23eb27f89a1066dc749de6a65c129ec48a5ea38f914fd0b95460`.

Изменения ограничены экспериментальным harness, новым набором случаев и
отчётом. Strict TypeScript typecheck и проверка исполняемых меток прошли.
