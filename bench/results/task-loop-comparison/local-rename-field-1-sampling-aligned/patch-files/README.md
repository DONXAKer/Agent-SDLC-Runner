# catalog

Каталог товаров: запись, хранение в JSONL, чтение обратно.

## Как устроено

| Модуль | Отвечает за |
|---|---|
| `src/product.ts` | Товар: артикул, название, цена в **копейках** целым числом. Конструктор `product()` проверяет то, что типом не выразить: пустой артикул, дробные или отрицательные копейки. |
| `src/store.ts` | Сериализация. Одна запись — одна строка JSON, файл — JSONL. Набор и порядок полей в строке закреплены. |
| `src/index.ts` | Публичный контракт: снаружи вызывают только его. |

## Формат строки каталога (JSONL)

| Поле | Тип | Что значит |
|---|---|---|
| `sku` | строка | Артикул (SKU) — идентификатор записи. Непустой. |
| `title` | строка | Название, как на витрине. |
| `priceK` | целое | Цена в копейках. |

Файл — строки JSONL: одна запись на строку, каждая завершена `\n`, пустые строки при чтении
пропускаются. Порядок полей в строке — как в таблице.

> Формат читают внешние службы (витрина, склад, выгрузка в бухгалтерию) — поля не
> переименовывают без совместимости: старые файлы обязаны читаться тем же кодом, что пишет
> новые.

## Совместимость: `code` → `sku`

Артикул переименован из `code` в `sku` (терминология приёмки и склада). Совместимость:

- Чтение (`parse`) принимает и старое имя `code`, и новое `sku` — старые файлы читаются.
  Если в строке оба имени, побеждает `sku`: новое имя пишет наш код, старое имя мог оставить
  ручной правкой файла.
- Запись (`serialize`) пишет только `sku`; ключ `code` в выходной строке нет — ни как поля,
  ни как дубля: строку с обоими именами внешние службы прочитают каждая по-своему.

## Как запускать

```bash
node scripts/build-check.mjs      # «сборка»: загрузка всех модулей src
node --test "test/**/*.test.ts"   # тесты
```

Компиляции нет: TypeScript исполняется напрямую, типы снимает Node (нужен 23.6 или новее).
Зависимостей у пакета нет, `npm install` не требуется.
