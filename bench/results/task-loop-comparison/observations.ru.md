# Наблюдения по устройству флоу

Серия завершена: 24/24 с выровненными параметрами. [Сводка](summary.ru.md), [ленты запусков](index.html).

- В guided baseline все восемь запусков остановились до реализации: семь — с `blocked`, один — по общему лимиту времени. В логах есть длительная генерация и ревью форм требований; встречается техническая остановка разрешения вопросов из-за запроса отсутствующего или пустого исходника. Это вывод о данной реализации в заданном бюджете, а не доказательство бесполезности планирования вообще.
- Прямой цикл той же локальной модели прошёл автоматическую приёмку в семи из восьми запусков. Границы файлов сохранились. Результат согласуется с гипотезой, что обязательные промежуточные документы и отдельные протоколы этапов были существенным препятствием. Четыре задачи не дают основания обобщать эффект на любые репозитории.
- После успешных автоматических проверок обнаружены два непокрытых крайних случая: явный `undefined` в частичном конфиге и `sku: null` при наличии старого поля. Оба дефекта повторились в обоих локальных запусках — четыре решения с подтверждёнными ошибками. Упрощение флоу не устраняет семантические ошибки модели; зелёный набор тестов не покрывает весь контракт.
- В первом запуске задачи с недостающим коэффициентом модель задала один нужный и два дополнительных вопроса. На лишние вопросы у банка нет ответа, поэтому результат — `needs_input`, без выдуманных данных. Один из вопросов ссылается на отсутствующую формулировку задачи. Во втором запуске модель задала только нужный вопрос и завершила задачу, пройдя также дополнительную проверку порядка округления.
- Ручной контроль текущим ассистентом показал, что доступных инструментов и зарегистрированных проверок достаточно для этих задач. Контроль несёт известный контекст и повторно использует подготовленные решения; сравнивать его с независимыми выборками модели нельзя.

Минимальный критерий перехода выполнен: валидатор прошёл оба повтора без выявленных ошибок. Всего без выявленных ошибок остались три локальных запуска из восьми; это не доказательство полной корректности. Следующий шаг — отдельные, заранее не разобранные задачи и проверка полноты критериев приёмки. Возвращать обязательного LLM-судью на каждом шаге или начинать дообучение только на основании этого малого пилота оснований нет. Для обучения нужны проверенные траектории и отдельный holdout; текущие ошибки и остановки следует сохранить в корпусе с корректными метками.
