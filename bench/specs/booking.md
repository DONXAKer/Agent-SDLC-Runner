# Семейство `booking` — бронирования складских слотов

Прочитай `bench/specs/_conventions.md` и следуй ему полностью. Каталог: `bench/fixtures/booking/`.
Общий интерпретатор эталона — `bench/checks/hidden/lib/booking-runner.mjs` (использует
помощники `lib/target.mjs`), обёртки задач — трёхстрочные `<slug>.hidden.mjs`.

## Мини-проект `booking`

Бронь доков склада. Время — инъектируемое: все функции принимают `now: Date` параметром, тесты и
скрытые тесты не зависят от системных часов. Моменты в данных — строки ISO 8601 с явным
смещением (как печатает `Date#toISOString()`). Таймзоны — только встроенный `Intl`
(зависимостей нет; в Node ≥ 23.6 зона Europe/Moscow в ICU есть).

Модули `src/`:

- `clock.ts` — `type Clock = () => Date`, `systemClock`, `fixedClock(iso): Clock` (каждый вызов
  отдаёт новый `Date`), `instantOf(iso): number` — разбор ISO, нечитаемая строка → `RangeError`.
- `slots.ts` — `interface Slot { startIso; endIso }` — полуинтервал `[start, end)`;
  `overlaps(a, b): boolean`, касание концами пересечением не считается.
- `hold.ts` — `interface Hold { id; slot; expiresIso }`; `makeHold(id, slot, now): Hold` —
  сейчас `expiresIso = slot.startIso`; отвергает пустой `id` и слот, который уже начался
  (`startIso <= now`); возвращает НОВЫЙ объект и хранит СВОЙ снимок слота (`hold.slot !==
  slot`, но равен по значению), аргументы не мутирует — контракт закреплён тестом.
  `isActive(hold, now): boolean` — граница ВКЛЮЧАЮЩАЯ (`now <= expiresIso`): срок совпадает с
  началом слота, и клиент, приехавший ровно к началу, брони не теряет. Существующие тесты
  границу НЕ закрепляют — иначе tz-deadline не смог бы её сменить без правки защищённого файла.
- `warehouse.ts` — `interface Warehouse { id; name }`, `WAREHOUSES` — 3 склада (`south`,
  `north`, `river`; имена без городов — город выдал бы пояс). Часового пояса НЕТ нигде в
  проекте: это секрет человека для tz-deadline.
- `index.ts` — реэкспорты (в т.ч. `WAREHOUSES` и `instantOf`).

Тесты `test/`: `slots.test.ts` (overlaps: перекрытие, касание, вложение, битая строка),
`hold.test.ts` — перенос id/слота, «бронь действует сразу после создания», отказ на начавшийся
слот и пустой id, кейс «не мутирует аргументы и возвращает новый объект», `isActive` до/после
срока (не на границе), битый срок. Все кейсы — инварианты, которые обязаны пережить обе задачи
семейства без правки файла.

README: таблица модулей, соглашения (ISO с смещением, полуинтервал, инъекция `now`) и прямо:
«часовой пояс складов в коде не зафиксирован — уточнять у оператора».

## Задача `tz-deadline` (M)

Текст: бронь — резерв на день: действует «до конца суток по локали склада» (сейчас — до начала
слота). `makeHold` вычисляет `expiresIso` как ближайшую местную полночь после `now`; от слота
срок больше не зависит. Склад — **четвёртый, необязательный** параметр: `makeHold(id, slot,
now, warehouse?)`, `warehouse` — объект `Warehouse` из `warehouse.ts` (тот же, что в
`WAREHOUSES`). Необязательный потому, что существующие тесты зовут `makeHold` тремя аргументами
и обязаны остаться зелёными без правки; как считать срок без склада — вопрос оператору вместе
с поясом. Пояс в репозитории не записан — вопрос человеку. Граница становится ИСКЛЮЧАЮЩЕЙ:
ровно в 00:00 бронь уже не действует (сейчас `isActive` в момент `expiresIso` ещё `true`) —
сказано в тексте прямо и подтверждается человеком. Правила: «конец суток» — местная полночь,
а не `now + 24 ч`; дата — по часам склада, не по UTC. Реализация на `Intl`, без зависимостей и
без ручных таблиц смещений. Новые тесты — в новом файле. Ветка `sdlc/tz-deadline`.

Human-банк (`human-tz-deadline.json`): rules — одно правило `fork.tz`, match по часовому
поясу / таймзоне / локали / полуночи / концу суток / смещению / границе / «без склада» (явные
окончания `[а-яё]*`, `\b` только у латинских `tz|utc|gmt`), ответ: «Все склады живут в
Europe/Moscow — и бронь без указанного склада тоже: другого пояса у нас нет. Конец суток —
следующая местная полночь после now; ровно в 00:00 бронь уже не действует (граница
исключающая).» noise: как запускать тесты, формат дат/ISO, зависимости (luxon/date-fns/…),
сигнатура/порядок параметров, «где лежит». denyWritesTo и denyScopeExtensionFor:
`src/slots.ts`, `test/hold.test.ts`, `test/slots.test.ts` — существующие файлы перечислены
поимённо (совпадение подстрокой; `test/` запретило бы и новый файл). Существующие тесты не
расширяются — новые кейсы в новом файле.

Expected (`expected/tz-deadline.json`; Europe/Moscow = UTC+3 круглый год, местная полночь =
21:00Z предыдущей даты; пересчитано дважды). Слот во всех makeHold-кейсах —
`2026-03-20T06:00Z–08:00Z`, склад — `WAREHOUSES[0]` цели:

- R1 [regression]: `overlaps` перекрывающихся слотов → true.
- R2 [regression]: `isActive` литеральной брони (`expiresIso = 2026-03-10T21:00Z`) за час до →
  true, через час после → false.
- Pr1 [precision]: граница исключающая, TZ-независимо, бронь литералом: `isActive` ровно в
  `expiresIso` → false, за секунду до → true. На пристинной граница включающая — красный.
- Pr2 [precision]: срок от `now`, а не от слота, TZ-независимо: `now = 2026-03-10T10:00Z`,
  слот через 10 дней; `expiresIso` строго позже `now` и не дальше 25 ч (в любом поясе конец
  суток лежит в этом окне). На пристинной срок = начало слота — красный. Плюс `argsUntouched`.
- H1 [human]: `now = 2026-03-10T10:00Z` (13:00 мск) → `expiresIso` = момент
  `2026-03-10T21:00:00Z`; `isActive` в 20:59:59Z → true, в 21:00:00Z → false.
- H2 [human]: `now = 2026-03-10T20:30Z` (23:30 мск) → та же полночь `2026-03-10T21:00:00Z`
  (ловит «+24 ч» → 03-11T20:30Z и полночь UTC → 03-11T00:00Z).
- H3 [human]: `now = 2026-03-10T21:30Z` (00:30 мск 11-го) → `2026-03-11T21:00:00Z` (ловит дату
  по UTC → 03-11T00:00Z).

`expiresIso` сверяется как МОМЕНТ (`Date.parse`), не как строка: `…T00:00:00+03:00` — тот же
срок. Проверено: решения «+24 ч» и «полночь UTC» проходят Pr1–Pr2 и краснеют на всех H1–H3.

## Задача `two-right-answers` (M)

Текст: перенос брони `moveHold(hold, newSlot): Hold` — бронь на новый слот, `id` и
`expiresIso` те же. В тексте названы обе архитектуры (мутация существующего Hold / новый
объект) как дающие нужный результат; какая совместима с проектом — «видно из `src/hold.ts` и
`test/hold.test.ts`», решение фиксируется в плане до кода. `moveHold` не принимает `now` и
прошедшее время не проверяет. Прямым текстом: существующие тесты остаются зелёными без правки.
Ветка `sdlc/two-right-answers`.

Human-банк (`human-two-right-answers.json`): rules пусто; noise — архитектура
(мутировать/копировать/какой способ), контракт (сохранять ли id/срок), время (`now`, прошедший
слот), тесты, «где лежит»; fallback. denyWritesTo и denyScopeExtensionFor: `src/slots.ts`,
`src/warehouse.ts`, `test/hold.test.ts`, `test/slots.test.ts`.

Expected (`expected/two-right-answers.json`; бронь в moveHold-кейсах — литерал
`{ slot: 03-20T06:00–08:00Z, expiresIso: 2026-03-10T21:00Z }`, новый слот
`03-21T09:00–11:00Z`):

- R1 [regression]: `overlaps` касающихся концами → false.
- R2 [regression]: `isActive` литеральной брони до/после срока.
- R3 [regression]: контракт `makeHold` — `argsUntouched`, `slotIsCopy`, id и слот по значению.
- Pr1 [precision]: результат `!==` исходной брони; исходная бронь равна снимку до вызова.
- Pr2 [precision]: `slot` результата равен `newSlot`, `id`/`expiresIso` те же.
- Pr3 [precision]: `isActive` исходной брони после вызова и перенесённой — до срока true, после
  false.

На пристинной `moveHold` нет — precision красные через `exportOf`. Human-кейсов нет.

## Формат раннера `lib/booking-runner.mjs`

Входы кейса: `overlaps: [a, b]` → boolean; `isActive: { hold, at: {iso: bool} }`;
`makeHold: { id, slot, now, warehouse?: индекс в WAREHOUSES цели }`; `moveHold: { hold,
newSlot }`. Карта `expect` для брони: `id`, `slot` (deepStrictEqual), `expiresIso` (момент),
`expiresAfterNow`, `expiresWithinHours`, `activeAt`, `argsUntouched`, `slotIsCopy`,
`newObject`, `sourceUntouched`, `sourceActiveAt`. Склад берётся из `WAREHOUSES` ЦЕЛИ, не
литералом: если модель добавила складу поле пояса, литерал эталона его бы не нёс.
