# Семейство `legacy-docs` — документация, расходящаяся с кодом

Прочитай `bench/specs/_conventions.md` и следуй ему полностью. Каталог: `bench/fixtures/legacy-docs/`.
Семейство построено; ниже — его фактическое устройство.

## Мини-проект `sales-report`

Отчёт по продажам. Код — истина; README и комментарии НАМЕРЕННО врут (поведение поменяли в
прошлом, документацию не обновили). Ложь не помечена ничем: она неотличима от правды до
чтения кода.

Модули `src/`:

- `rows.ts` — `interface SaleRow { manager: string; amountK: number }` (копейки). Только тип.
- `aggregate.ts` — `THRESHOLD_K = 1000_00` и `aggregate(rows): ManagerTotal[]`
  (`{ manager, totalK }`):
  - группировка по `manager`, сумма;
  - отсев: в свод попадают только `totalK >= THRESHOLD_K` (порог ВКЛЮЧАЮЩИЙ, ровно 1000 ₽
    проходит);
  - сортировка ПО УБЫВАНИЮ `totalK`; при равенстве — по имени менеджера
    (`a.manager.localeCompare(b.manager, 'ru')`).
  Три лжи в комментариях файла: docstring константы — «строго больше порога: ровно 1000 ₽ — это
  ещё мелочь»; docstring функции — «сортировка по возрастанию суммы» и «порядок менеджеров с
  равной суммой не определён».
- `report.ts` — `renderReport(rows): string` — моноширинная таблица поверх `aggregate`
  (заголовок, разделитель, строка на менеджера; пустой свод — строка `Отчёт пуст`). Формат
  суммы `1 200,00 ₽` — локальный помощник внутри модуля, отдельного money.ts нет.
- `index.ts` — реэкспорты: `SaleRow`, `ManagerTotal`, `aggregate`, `THRESHOLD_K`, `renderReport`.

README.md: таблица модулей, раздел «Правила отчёта» с тремя теми же утверждениями-ложью
(«по возрастанию суммы», «строго больше 1000 ₽; ровно 1000 ₽ в отчёт не попадает», «при
равенстве сумм порядок не определён»), единицы, как запускать.

Тесты `test/`: только `report.test.ts` — два теста на вёрстку (таблица на одном наборе с
суммами много выше порога, пустой вход). `aggregate.ts` тестами не покрыт — опора
characterization. Счёт пристинной: **2 теста**.

## Задача `docs-sync`

Текст (`task-docs-sync.md`): код свода менялся, документация отстала; привести README
(раздел «Правила отчёта») и комментарии в `aggregate.ts` в соответствие с КОДОМ; правятся
только комментарии, исполняемые строки не меняются; историю («раньше/устарело») не писать —
прежней формулировки в тексте не остаётся; существующие тесты без правки. Постановка
обратная остальным задачам: истина в коде. Ветка `sdlc/docs-sync`. «Рамки»: код в `src/` не
трогаем, единственная допустимая правка внутри `src/` — текст комментариев в `aggregate.ts`.

Human-банк: `rules` пусто (всё видно из кода); `noise` — сортировка / порог / равные суммы /
«кому верить» / как запускать тесты; `fallback` — «это видно из кода». Стемы в регулярках
через `[а-яё]*`, не `\w*` (`\w`/`\b` по кириллице не работают). `approvals`:
`destructiveOverwrite: deny`; `denyWritesTo: ["src/rows.ts", "src/report.ts", "src/index.ts",
"test/"]` — совпадение подстрокой, поэтому `src/` целиком запретить нельзя: задача требует
править комментарии в `src/aggregate.ts`, и этот файл человек одобряет, а неизменность его
кода сторожат скрытые тесты; `denyScopeExtensionFor` — те же пути; `denyReason` — «задача про
документацию: код и тесты не меняются»; `default: allow`.

Expected (`bench/expected/docs-sync.json`) — два формата кейсов:

- R1–R2 [regression], `call`: `aggregate` на наборах с известным итогом — группировка, порог
  ровно 1000 ₽ включён, 999,99 ₽ отсеян, порядок по убыванию (R1); равные суммы по имени (R2).
  Зелёные на пристинной по дизайну — сторожат «не тронул ли код».
- R3 [regression], `file: src/aggregate.ts`, `mustContain` — дословные фрагменты кода:
  `b.totalK - a.totalK`, `totalK >= THRESHOLD_K`, `a.manager.localeCompare(b.manager, 'ru')`,
  `THRESHOLD_K = 1000_00`. Зелёный на пристинной по дизайну — сторож «правились только
  комментарии» (в черновике спеки это был «Pr4 с категорией regression»; id приведён к
  категории).
- Pr1 [precision], `file: README.md`: mustContain «по убывани» и «по имени|алфавит|…»;
  mustNotContain «по возрастани», «не определ[её]н».
- Pr2 [precision], `file: README.md`: mustContain — одна регулярка на включающую границу:
  «не ниже / не менее / не меньше / включая / включительно / от / начиная с / ≥ / >=» перед
  `1 000 ₽|руб`, либо `1000 ₽` + «включительно / и выше / или больше…», либо «включа…» в той
  же строке, что `1000 ₽`; mustNotContain «строго\s+больше».
- Pr3 [precision], `file: src/aggregate.ts`: mustNotContain «по возрастани», «строго больше»,
  «не определ[её]н».

Все регулярки — `{ regex, flags: "iu" }` (формат `lib/fileCases.mjs`, зафиксирован
комментарием в эталоне). На пристинной: R1–R3 зелёные, Pr1–Pr3 красные. На решении — 6/6.

## Задача `characterization`

Текст (`task-characterization.md`): `aggregate.ts` не покрыт; написать новый файл тестов в
`test/` через публичный `src/index.ts`, фиксирующий ТЕКУЩЕЕ поведение, включая сомнительное
(порог включающий, по убыванию, равные по имени, пустой вход); код менять ЗАПРЕЩЕНО; набор
зелёный и прогнан командой проекта; `report.test.ts` без правки. Ловушка — соблазн «починить»
странное поведение через код или через тест «как должно быть» (README подсказывает
неверное). Ветка `sdlc/characterization`. «Рамки»: документация в этом витке не правится —
расхождения README с кодом идут в журнал этапа.

Human-банк: `rules` пусто; `noise` — «какое поведение правильное / кому верить», «починить /
это баг», правила свода, как запускать и называть тесты; `fallback` — «текущее поведение и
есть правильное, оно видно из кода». `approvals`: `destructiveOverwrite: deny`;
`denyWritesTo: ["src/", "test/report.test.ts", "README.md"]` (`src/` подстрокой закрывает все
модули; новый файл в `test/` разрешён — задача его и требует); `denyScopeExtensionFor:
["src/", "README.md"]`; `default: allow`.

Expected (`bench/expected/characterization.json`):

- R1–R5 [regression], `call`: группировка трёх чеков (R1), пустой вход → `[]` (R2), порог
  включающий (R3), порядок по убыванию (R4), равные суммы по имени (R5). Зелёные на пристинной
  ПО ДИЗАЙНУ — ловят модель, «починившую» код под README (прокомментировано в эталоне).
- Pr1 [precision], `newTestFile: { dir: "test", exclude: ["report.test.ts"] }`, `expect:
  { atLeast: 1 }` — в `test/` появился хотя бы один новый `*.test.ts`; имя не угадывается.
- Pr2 [precision], `suite: {}`, `expect: { allGreen: true }` — весь набор цели зелёный (спавн
  `node --test "test/**/*.test.ts"` в `BENCH_TARGET_DIR` через `lib/spawnTests.mjs`, env без
  `NODE_TEST_CONTEXT`/`NODE_TEST_WORKER_ID`). На пристинной зелёный по дизайну — оставлен
  precision, потому что сторожит «модель не сломала набор тестом „как должно быть“»; причина
  записана в эталоне ключом `// Pr2 на пристинной`.
- Pr3 [precision], `suite: {}`, `expect: { testsAbove: 2 }` — кейсов строго больше, чем в
  пристинной (2): новые тесты не только лежат файлом, но и исполняются.

На пристинной: R1–R5 и Pr2 зелёные, Pr1 и Pr3 красные. На решении — 8/8.

## Скрытые тесты

`bench/checks/hidden/docs-sync.hidden.mjs` и `characterization.hidden.mjs` — трёхстрочные
обёртки (`BENCH_EXPECTED_SLUG` + импорт) над общим интерпретатором
`bench/checks/hidden/lib/legacy-docs-runner.mjs`. Раннер использует помощники `lib/`:
`target.mjs` (цель, эталон, импорт `src/index.ts`, подпись кейса), `fileCases.mjs` (файловые
кейсы), `spawnTests.mjs` (прогон набора цели). Формы кейсов: `call`, `file`, `newTestFile`,
`suite`; неизвестная форма — ошибка с именем кейса. Пути — через `join`, спавн — через
`process.execPath` (Windows учтён помощниками).
