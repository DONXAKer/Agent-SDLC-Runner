# Семейство `billing-bug` — счета с двумя посеянными багами

Прочитай `bench/specs/_conventions.md` и следуй ему полностью. Каталог: `bench/fixtures/billing-bug/`.

_Спека приведена к построенному семейству: числа ниже — итоговые, пересчитаны вручную дважды
по константам фикстуры и сверены скрытыми тестами на пристинной и на эталонном решении._

## Мини-проект `billing-bug`

Выставление счетов (как `billing`, но СВОЙ проект — ничего не импортирует из другого
семейства). Содержит ДВА независимых бага в РАЗНЫХ модулях. Ограничение-критерий: оба бага
НЕВИДИМЫ для существующих тестов (набор пристинной зелёный: **12 кейсов**, 3 файла) — баги
вне текущего покрытия. Это принципиально: красная пристинная фикстура = сломанный бенчмарк.

Модули `src/`:

- `money.ts` — приёмы как в `bench/fixture/src/money.ts` (Kopeck, rub, add, subtract с clamp,
  percent — половина вверх, formatRub). money.ts ВЕРЕН (опора wrong-diagnosis: ТЗ клевещет
  на него).
- `lines.ts` — `interface Line { title: string; qty: number; priceK: Kopeck; discountPct?:
  number }`, `lineTotal(line): Kopeck`, `subtotal(lines): Kopeck`.
  БАГ B (для wrong-diagnosis): при наличии `discountPct` lineTotal считает скидку С КАЖДОЙ
  ЕДИНИЦЫ: `qty * (priceK - Math.round(priceK * pct / 100))` вместо `priceK*qty` и одного
  percent на всю строку. На границах округления расходится на копейки (qty=3, priceK=333,
  pct=7: верно percent(999,7)=70 → 929; баг: 333−Math.round(23.31)=310, ×3=930).
  Существующие тесты lines используют только «круглые» значения, где оба способа совпадают
  (2×500 при 10% → 900; 1×1000 при 25% → 750; 4×250 при 20% → 800). Комментарий рядом
  нейтральный («скидка на строку»), баг не подсвечен.
- `invoice.ts` — `interface Invoice { number: string; lines: readonly Line[]; deliveryK:
  Kopeck; discountPct: number; subtotal: Kopeck; total: Kopeck }`, `buildInvoice(number,
  lines, deliveryK, discountPct): Invoice`.
  БАГ A (для bug-by-symptom): скидка считается от `subtotal + deliveryK` (percent от суммы
  С ДОСТАВКОЙ), а по правилам (README) — только от subtotal; и total вычисляется как
  `subtotal + deliveryK − discount` БЕЗ clamp. Существующие тесты invoice: большие суммы с
  discountPct=0 и скидка при deliveryK=0 (самовывоз) — на обоих оба способа совпадают, бага
  не видят.
  **Про «минус».** При pct ≤ 100 percent(subtotal+deliveryK, pct) ≤ subtotal+deliveryK, и
  total этой формы в отрицательные не уходит арифметически: на мелком заказе
  (subtotal=50, delivery=100, pct=100) баг даёт 150−150 = **0**, а не −50 (в черновике спеки
  была ошибка счёта). Симптом в тексте задачи поэтому — «итог меньше стоимости доставки,
  вплоть до нуля: доставку никто не оплачивает». Отсутствие clamp остаётся частью посева
  (README: «итог не бывает отрицательным», эталонная правка — через `subtract`), но скрытым
  тестом отдельно не измеряется: при верной базе скидки clamp на pct ≤ 100 не срабатывает.
- `index.ts` — реэкспорты + фасад `bill(number, lines, deliveryK = 0, discountPct = 0)`.

Тесты `test/`: `money.test.ts` (5), `lines.test.ts` (4), `invoice.test.ts` (3) — все зелёные
на пристинной (проверено: баги не задевают ни один кейс). README: раздел «Правила расчёта»:
скидка позиции — один процент от стоимости всей строки, округление один раз на строку;
«скидка счёта — от стоимости товаров, доставка не дисконтируется; итог не бывает
отрицательным» — README ПРАВИЛЬНЫЙ, код врёт (находка для модели — по README и симптому).

Общий интерпретатор эталона семейства — `bench/checks/hidden/lib/billing-bug-runner.mjs`
(формы кейсов: `call`, `bill`, `suite` — набор цели гоняется дочерним `node --test`, `untouched`
— git status по путям со skip без `.git`). Обёртки задач — трёхстрочные `<slug>.hidden.mjs`.

## Задача `bug-by-symptom` (M)

Текст — ТОЛЬКО симптом, без указания места: две жалобы поддержки — у покупателей с мелким
заказом и большой скидкой итог меньше стоимости доставки, вплоть до нуля; у обычных заказов
скидка иногда на копейки-рубли больше, чем по оферте («скидка — от суммы товаров»). Модель
обязана локализовать: скидка берётся от суммы с доставкой (оба симптома — одна причина; clamp
— страховка по README). Правка — invoice.ts: percent от subtotal, total через subtract.
Место в тексте не подсказывается. Ветка `sdlc/bug-by-symptom`. Требование: новый
регрессионный тест на оба симптома **отдельным файлом** в `test/` (существующие тестовые
файлы закрыты на запись), набор прогнан.

Human-банк: rules пусто (README + симптом исчерпывают), noise: «где баг», база скидки,
округление, «в минус/clamp», как гонять тесты → fallback «видно из кода и README».
denyWritesTo: `src/money.ts`, `test/money.test.ts`, `test/lines.test.ts`,
`test/invoice.test.ts` (совпадение подстрокой — перечислены файлы, а не каталог `test/`,
чтобы новый тестовый файл прошёл; оговорено комментарием в human-файле).
denyScopeExtensionFor: `src/money.ts`.

Expected (`bench/expected/bug-by-symptom.json`; в пристинной 12 кейсов):
- R1 [regression]: `percent(105, 10) === 11`.
- R2 [regression]: `subtotal([2×333, 1×334]) === 1000`.
- Pr1 [precision]: мелкий заказ `bill(_, [1×50], 100, 100)` → subtotal 50, **total 100**
  (баг: 0).
- Pr2 [precision]: скидка НЕ от доставки: `bill(_, [1×1000], 500, 10)` → subtotal 1000,
  **total 1400** (баг: percent(1500,10)=150 → 1350).
- Pr3 [precision]: discountPct=0: `bill(_, [1×1000], 500, 0)` → total 1500 — поведение
  прежнее. Зелёный на пристинной ПО ДИЗАЙНУ (сторож, как Pr3 у vat-rounding).
- Pr4 [precision]: набор тестов цели зелёный и в нём > 12 кейсов — новый регрессионный тест
  появился (добавлено сверх черновика: требование «новый тест» иначе не измерялось).
- H-кейсов нет.

На пристинной: 3 зелёных (R1, R2, Pr3), 3 красных (Pr1, Pr2, Pr4). На эталонном решении: 6/6.

## Задача `wrong-diagnosis` (M)

Текст: жалоба — строка счёта со скидкой на копейку-две дороже, чем по калькулятору;
«скорее всего дело в округлении в `src/money.ts` — проверь `percent`». ЛОВУШКА: money.ts
верен (percent — половина вверх, покрыт тестами, в т.ч. `percent(999,7)=70`); баг в lines.ts
(поштучное округление скидки). Модель обязана опровергнуть гипотезу ТЗ фактом (тесты money
зелёные) и починить lines.ts: скидка одним percent на строку. «Починка» money.ts ломает его
тесты — детектор. Ветка `sdlc/wrong-diagnosis`. Требование: регрессионный тест на границе
округления (рядом с существующими — в `test/lines.test.ts` писать можно).

Human-банк: rules: tag `fork.money`, match `(money|percent|округл|половин)` → ответ:
«percent проверен и покрыт тестами — ищи, кто считает мимо него.» (честная подсказка, не
шум: направляет, но не называет файл; правила проверяются раньше шума). noise остальной.
denyWritesTo: `src/money.ts`, `test/money.test.ts`; denyScopeExtensionFor: `src/money.ts`;
denyReason: «money.ts проверен, баг не в нём».

Expected (`bench/expected/wrong-diagnosis.json`; в пристинной 12 кейсов):
- R1 [regression]: `percent(999, 7) === 70` (модуль money верен — зелёный на пристинной).
- R2 [regression]: `lineTotal({qty:2, priceK:333}) === 666`.
- Pr1 [precision]: `lineTotal({qty:3, priceK:333, discountPct:7}) === 929` (баг: 930 —
  расхождение вверх).
- Pr2 [precision]: `lineTotal({qty:2, priceK:250, discountPct:5}) === 475`: percent(500,5)=25;
  баг: 250−Math.round(12.5)=237, ×2=474 — расхождение вниз, ловит подгонку под одно число.
- Pr3 [precision]: `lineTotal({qty:3, priceK:333}) === 999` — строка без discountPct,
  поведение прежнее. Зелёный на пристинной ПО ДИЗАЙНУ (сторож).
- Pr4 [precision]: набор тестов цели зелёный и в нём > 12 кейсов (добавлено сверх черновика).
- H1 [human]: money.ts не изменился — `git status --porcelain -- src/money.ts` пуст (skip
  без `.git`, паттерн `lib/gitState.mjs`). Факт «money верен» — из ответа человека.

На пристинной: 3 зелёных (R1, R2, Pr3), 3 красных (Pr1, Pr2, Pr4), H1 пропущен (нет `.git`).
На эталонном решении (копия с `git init`): 7/7, без пропусков. Негативный контроль: тронутый
`src/money.ts` (percent через Math.round) красит H1, Pr1, Pr2 и Pr4.
