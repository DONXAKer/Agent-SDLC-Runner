# Парное сравнение обвязки

Команда использует существующий guided benchmark. Модель и независимые проверки одинаковы;
варианты отличаются ровно объявленным текстовым изменением. Автоматического изменения
проверок, генерации исправлений и применения уроков нет.

```powershell
npm run bench:harness -- prepare --spec bench/experiments/harness-verify-claims.json --output bench/results/harness-verify-claims-pilot
npm run bench:harness -- run --output bench/results/harness-verify-claims-pilot
npm run bench:harness -- resume --output bench/results/harness-verify-claims-pilot
npm run bench:harness -- report --output bench/results/harness-verify-claims-pilot
```

`prepare` требует новый каталог. Сохраняет рабочие исходники B, создаёт A заменой
единственного объявленного фрагмента, копирует эффективную конфигурацию, методологию,
skills/agents и зависимости. Можно передать `--baseline ROOT --candidate ROOT`:
копируются оба готовых дерева, а допустимость единственного изменения всё равно проверяется.
Оригинальные исходники не редактируются. Символические ссылки во входах запрещены;
workspace-зависимость shared разрешается в собственную копию каждого варианта.

`run` ждёт заданных порогов GPU, поднимает отдельный локальный Ollama на свободном порту,
подтверждает кэш, контекст, модель и GPU-размещение. Четыре запуска идут A/B и B/A,
с выгрузкой модели между ними. Модель-судья отдельно не запускается.
Каждая попытка получает уникальные slug и каталог состояния. Запуски идут из одинаковых
исходных fixture через штатный механизм benchmark; ответы человека и скрытые тесты
не копируются в доступное модели дерево.

После прерывания `resume` сохраняет завершённые ячейки; незавершённая получает новый
slug, старые артефакты остаются. Живой процесс незавершённого запуска блокирует повтор.
Бюджет ячейки не сбрасывается: после корректного прерывания доступен остаток;
при аварии без известного времени завершения консервативно списывается весь лимит.
Ячейка с исчерпанным бюджетом остаётся без оценённого результата, а не успешной.
Файл `run.lock` защищает от параллельного запуска серии. При изменении замороженных
входов нужен новый эксперимент. После аварии процесса оставшийся движок на выделенном
порту нужно сначала проверить и завершить: команда не присваивает чужой сервер.

В каталоге результата: `manifest.json`, точный `change.diff`, `report.ru.md`,
`lesson.json`, конфигурация/снимки и отдельные артефакты каждого вызова. Локальные
конфигурации могут содержать машинные пути; каталог снимков предназначен для локального
воспроизведения. Для публикации использовать отчёт и проверенные артефакты.
Каталоги `common`, `snapshots`, `state` и `runs` исключены из Git; манифест и отчёт сохраняются.

По одному запуску варианта не устанавливает статистическую устойчивость. Достижение
Verify ещё не доказывает исполнение изменённой ветви. Без подтверждения целевого
сбоя и его устранения урок остаётся `candidate`. Уроки не включаются в runtime-промпты.

Сырые трассы записываются по абсолютному `rawLogDir` из invocation в манифесте.
Отсутствующие, повреждённые или неполные трассы показываются как `incomplete`;
число отказов при этом неизвестно, а не равно нулю.

Для завершённого старого эксперимента можно восстановить измерения без GPU:

```powershell
node tools/harness-comparison.ts recover-evidence --output bench/results/harness-verify-claims-pilot-v6-20261020
```

Команда создаёт `evidence-recovered.json` и `report.recovered.ru.md`, сохраняя исходные
манифест, результаты и снимки. Для старых invocation без `rawLogDir` поддерживается
ошибочно использованный каталог `snapshots/<arm>/1/<slug>`. В восстановлении
сохраняются хеш исходного манифеста и версия сборщика.

Guided и state-first требуют защищённой регистрации независимого набора после одобрения
плана и до реализации. При отсутствии набора современный шаблон блокирует Chunk и прямой
вход в Verify. Результат Docker входит в вердикт, устаревшие свидетельства закрывают Handoff.
Для пяти задач стенда набор подключается явным `--acceptance-image <локальный образ Node 24>`;
его фиксированные определения находятся в `bench/acceptance/`, отдельно от скрытого оценщика.
Старый A/B runner этот флаг не передаёт: для нового полного сравнения используется
`tools/guided-matrix.ts` и `bench/experiments/guided-matrix-acceptance.json`.

Контекст связанных требований теперь общий для обоих вариантов свежего эксперимента.
Старые снимки не меняются. Следующее сравнение Verify следует проводить на одинаковом
сохранённом состоянии перед проверкой. Полная матрица измеряет весь цикл и не изолирует
влияние одной правки Verify. Общий автоматический replay этапа пока не реализован.
