# Полная матрица с независимой приёмкой

`guided-matrix-acceptance.json` задаёт шесть установленных локальных моделей и пять задач.
Один повтор на пару, 30 минут на весь цикл, 15 минут на этап, до трёх попыток.
Общий сторож — 24 часа; ожидание свободных GPU — до 15 минут перед каждой парой.
Матрица сохраняет незавершённые пары при истечении бюджета и не объявляет их провалом модели.

```powershell
node tools/guided-matrix.ts prepare --output bench/results/guided-matrix-acceptance-20261020
node tools/guided-matrix.ts run --output bench/results/guided-matrix-acceptance-20261020
```

Подготовка замораживает исходники, зависимости, методологию, определения приёмки,
параметры моделей и неизменяемый ID локального Docker-образа Node 24. Изменения рабочего
репозитория после подготовки не попадают в измерение. На каждой паре сверяются хеши
снимка и конфигурации; общий сервер Ollama не используется и не завершается.

Для экономии диска `prepare --reuse-dependencies bench/results/<завершённый-стенд>`
переиспользует зависимости из ранее замороженного стенда. Проверяются отсутствие
активного запуска, версия Node, lockfile и хеши исходного набора до и после операции.
На одном томе создаются жёсткие ссылки; структура каталогов и проверка содержимого
остаются отдельными для каждого стенда. Это неизменяемые входы: для обновления пакетов
нужен новый снимок. Ссылки на изменяемый рабочий node_modules не создаются.
Используются CUDA12, q8 KV, один запрос за раз. Проверяются эффективные буферы CUDA,
тип KV и объявленная политика размещения (`gpu-only` по умолчанию, `hybrid` для Devstral).
Гибридный профиль допускает CPU offload, но не отсутствие CUDA; его время нельзя напрямую
сравнивать с полностью GPU профилями. Окно каждой модели сохраняется из её
профиля: Devstral 16k, остальные 32k. Это ограничивает прямое сравнение скоростей.

Перед матрицей каждая модель проходит два повтора четырёх протокольных проверок:
приоритет по источнику, различение объявлений, no_change и адресная карточка ремонта.
Общий лимит — 15 минут на модель, включая загрузку. Это проверка совместимости протокола,
а не доказательство прохождения полного SDLC. Отказ параметра не вызывает скрытого
переключения режима. Результаты и сырые ответы записываются в `qualification-N.json`
и `manifest.json`. Если хотя бы один профиль не прошёл, матрица не начинается.
NeoHorse и Qwen используют reasoning_effort=none; GPT-OSS — low. Параметры подтверждаются
фактическими запросами, совместимость не выводится из названия модели.

После успешного плана стенд регистрирует фиксированный набор из `bench/acceptance/`.
Тесты написаны по исходному заданию до реализации, запускаются отдельно без сети с
кандидатом и набором только для чтения. Проверяются поведение, политика существующих
тестов, наличие новых тестов, сборка и фактический запуск тестов проекта. Общий набор
сопоставляется всем автоматическим пунктам одобренного контракта; это не доказательство
семантического покрытия каждого сгенерированного пункта. Проверка лишних требований
остаётся за проработкой и ревью. Скрытые тесты не передаются в приёмочный набор.

`manifest.json` и `summary.ru.md` содержат текущую пару, исход, причину остановки и
метрики. `runs/` содержит отдельные журналы/артефакты, `raw/` — запросы модели,
`engine.log` — эффективные параметры движка. Для остановки послать SIGINT координатору;
он завершает только собственные дочерние процессы. Автоматического перезапуска
незавершённой пары нет: нельзя обнулить потраченный бюджет повторным стартом.

Симуляции без GPU: `acceptance-recovery-state-first-20261020` (7 сценариев) и
`acceptance-recovery-guided-v4-20261020` (10 сценариев). Сообщённый конфликт требований
остаётся ⚠ и блокирует положительный вердикт; эти тесты не доказывают, что модель
сама найдёт всякое противоречие естественного языка.
