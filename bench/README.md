# Бенчмарк моделей

Прогон одной и той же фикстурной задачи по витку методологии на разных моделях, с фиксацией
статуса и метрик каждого этапа и механической сверкой итога с эталоном.

Зачем: девять записей `docs/model-runs.md` собраны вручную, каждая по своей задаче на своём
проекте. «Модель не тянет этап 5» там неотделимо от «задача была другая». Здесь старт у всех
моделей побайтово одинаковый, а вывод делает код, а не глаз.

## Состояние

Готово: фикстура (`fixture/`), разбор аргументов, раскладка маршрутов, подготовка рабочей
копии и **сухой прогон**.

```bash
npm run bench -- --dry-run
```

Сухой прогон готовит копию фикстуры в tmp, поднимает настоящий `Run` и печатает блокеры всех
семи этапов, **ни разу не обратившись к модели**. Зелёный означает, что до модели дело дойдёт:
набор гейтов собран, ветка витка сошлась, профиль разрешился. Это самая дешёвая проверка из
существующих, и запускать её надо первой после любой правки фикстуры.

Не сделано: автоответчик человека, драйвер этапов, сбор метрик, эталон и сверка, отчёт.
Живой прогон отвечает «ещё не реализован» и кодом 2. Что и в каком порядке строить дальше —
`ROADMAP.md`.

## Как устроено

| Каталог | Что |
|---|---|
| `fixture/` | Мини-проект `parcel-price` + `.sdlc/gates.md` + `task.md` + `human.json`. Копируется в tmp целиком. |
| `src/` | Обвязка: аргументы, маршруты, рабочая копия, CLI. |
| `test/` | Герметичные тесты обвязки. Входят в общий `npm test`. |
| `control.json` | Контрольный маршрут «этап → модель». |
| `baseline/` | Замороженные контрольные прогоны — в репозитории. |
| `results/`, `snapshots/` | Вывод прогонов — в `.gitignore`. |

Сам бенчмарк в `npm test` не входит: он стоит денег и минут, ходит в сеть, недетерминирован
по построению и требует эталона методологии на диске. Красный бенчмарк не означает регрессию
раннера.

## Ограничение, которого не обойти

Правило рецензента требует строго `rank(verify) > rank(chunk)`. **Прогнать одну модель на всём
витке невозможно**: этап 6 всегда идёт по более сильному маршруту. Режим `--all` означает
«измеряемая модель везде, кроме `verify`», и читать его иначе нельзя. Попытка измерить слабую
модель на `verify` даёт «профиль не собрался» и код 2 — это «не измерено по правилу
рецензента», а не отказ модели.

## Что бенчмарк НЕ меряет

- **Артефакты бенч-витка подписаны автоответчиком** под именем «Бенчмарк». Их нельзя
  коммитить и нельзя выдавать за пройденный виток.
- **Автоответчик разрешительнее живого оператора.** Он говорит «да» почти всему, отказывая
  только по декларации `fixture/human.json`. Результат — верхняя оценка, а не поведение в бою;
  все его решения обязаны попадать в отчёт, чтобы зелёный, полученный чужим «да», читался как
  таковой.
- **`friction` есть только у флоу `loop`.** `SdkExecutor` не считает ни повторов, ни битого
  JSON, ни отказов политики. В отчёте это «не изм.», никогда не ноль.
- **При `costUsd === null` бюджет не действует вообще.** На локальных провайдерах
  ограничителями остаются ходы и стенные часы, и это пишется в каждый такой отчёт. У рублёвых
  агрегаторов стоимость недостоверна: известный дефект учёта валюты кладёт рубли в поле
  долларов.
- **Меряется связка**, а не модель: модель + промпты методологии + набор гейтов + раннер.
  Смена любого звена меняет результат, поэтому контрольный прогон переснимается после каждой
  правки промптов или рантайма.
- **Одна экосистема.** Фикстура — node/TS. На C#, Python и Unreal поведение гейтов, детект
  сборки и размер промпта другие.
- **Один прогон — наблюдение, а не измерение.** Два прогона одной модели могут разойтись в
  статусе этапа. Записывать надо оба, а не усреднять.

## Фикстура

`parcel-price` — расчёт цены доставки: тарифная таблица по зонам и весу, скидка лояльности,
деньги в копейках. Задача (`fixture/task.md`) — добавить надбавку за негабарит. Она щупает
модель с четырёх сторон:

| Щуп | Чем задан |
|---|---|
| правка + новый файл + новый тест с реальным прогоном | `priceFor` получает поле, правило живёт отдельным модулем, на него есть тест |
| граница плана | `src/discounts.ts` выглядит уместным местом правки, но задача закрывает вопрос прямо |
| разрушающая перезапись | `src/tariffs.ts` обязан быть в плане, а правка в нём — на три строки из 215 |
| вопрос человеку | ставка для суммы измерений свыше 300 см не записана нигде: её нельзя вывести, только спросить |

Фикстура обязана оставаться зелёной сама по себе:

```bash
cd bench/fixture
node scripts/build-check.mjs      # 5 модулей из 5
node --test "test/**/*.test.ts"   # 13 из 13
```

Красная фикстура означает сломанный бенчмарк, а не плохую модель.
