## Проблема

После перехода guided-флоу на вопросы и JSON все шесть запусков GPT-OSS 20B, Ministral 3 14B и Qwen 3.8 27B IQ4 остановились до реализации. Нужно устранить ошибки интерфейса и восстановления, сохранив проверки безопасности и честный итог бенчмарка.

## Данные анализа HTML

Серия: `bench/results/json-flow-final-20261009065718375/index.html`. Отдельные HTML содержат реальные HTTP, вопросы, ответы, инструменты, изменения документов и отказы. 32 HTTP-запроса, 0/6 завершённых задач; скрытые тесты не запускались. Две задачи: add-validator и config-default.

| Модель / задача | Где остановилась | Подтверждённое поведение |
|---|---|---|
| GPT-OSS / add-validator | explore | Read каталога src → EISDIR |
| GPT-OSS / config-default | intent | виртуальный источник request-1 использован как путь файла |

У последнего ремонта сохранились все заголовки и 10 ID приёмки. Это доказывает ложность одного лишь критерия количества строк, но не доказывает полную семантическую эквивалентность содержимого. Ошибки выбора инструментов подтверждены; отсутствие различения видов источников и отсутствие восстановления — направления решения, которые нужно проверить тестами.

## Предлагаемое решение

1. Передавать каталог источников с явными видами: встроенный запрос, существующий файл, каталог, планируемый файл. Встроенный источник читается по ID рантаймом, каталог перечисляется, отсутствующий планируемый файл не предлагается как доступный для Read. Сохранить исходный код и пользовательский текст без переразметки. Не подменять опечатки автоматически похожими путями.
2. Формировать JSON-схему действий из реально доступных на этапе прав. Неподдерживаемое действие возвращает структурированную ошибку и допустимые варианты. При вопросе человеку использовать существующий разрешённый переход к проработке, без самовольного ответа модели и расширения прав.
3. После ошибки чтения/неверного выбора вернуть вопрос, ошибку и доступные источники модели на ограниченный повтор. Первое решение остаётся гипотезой. Ограничить повторы, исключить циклы, учитывать бюджет, таймаут и отмену; нарушение безопасности не обходить повтором.
4. Ремонтировать только адресованные разделы через существующий гейт. Для служебного документа различать изменение оформления и потерю типизированных фактов. Сохранять ID, критерии, основания, цитаты и нетронутые разделы; проверять фактическое содержимое, а не только число строк. Реальная потеря данных и ручные изменения по-прежнему блокируют запись. Не вводить общее автоодобрение короткой перезаписи.
5. В HTML показывать доступные источники/действия, ошибочный выбор, обратную связь, повтор, изменения фактов и точную причину гейта. Отдельно отображать валидный JSON и разрешённую запись: первое не означает второе.

## Критерии приёмки

- [ ] На воспроизводимых сценариях все пять ошибок выбора выше либо предотвращаются схемой, либо дают ограниченный корректирующий повтор без аварийного завершения на первом промахе.
- [ ] Недоступный AskHuman не выполняется; дальнейший переход использует существующие права и правила проработки.
- [ ] Преобразование JSON в таблицу с сохранением всех проверенных фактов проходит гейт; удаление критерия, основания, цитаты, изменение ID или нетронутого раздела блокируется.
- [ ] Обработаны повтор одинаковой ошибки, исчерпание бюджета, отмена и изменение документа между проверкой и записью.
- [ ] Интеграционные проверки проходят через существующие исполнители, инструменты и гейт; не ограничиваются проверкой вспомогательного форматтера.
- [ ] Для каждого повтора HTML связывает вопрос, данные, HTTP, ответ, проверку, разрешение записи и изменение файла без ложного переноса успешной проверки на предыдущий отказ.
- [ ] Повторена та же матрица из шести запусков на одной зафиксированной версии кода с прежними лимитами и strict-questions. Опубликованы шесть HTML и сравнение с исходной серией.
- [ ] Успех заявляется только после реализации, независимой проверки, handoff и скрытых тестов. Остановка до этих этапов не считается успехом. Улучшение процента успеха оценивается отдельно от исправления воспроизводимых ошибок протокола.

## Проверки и ограничения

Сначала детерминированные интеграционные сценарии на границе исполнителя/инструментов/гейта, затем шесть локальных запусков. Не ослаблять scope, права, независимую проверку или гейт ради результата. Не обещать качество модели по прохождению только intent. Использовать текущие незакоммиченные изменения guided JSON в рабочем каталоге, не откатывать их.
