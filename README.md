# Agent-SDLC Runner

Тонкий сервис под один виток методологии [Agent-SDLC](https://github.com/): семь этапов
(`ЦЕЛЬ → РАЗВЕДКА → ВОПРОСЫ → ПЛАН → CHUNK → ВЕРИФИКАЦИЯ → COMMIT`) с видимыми запросами
к модели, одобрением записи файлов до её применения и учётом стоимости.

Артефакты витка пишутся в `.sdlc/<slug>/` целевого проекта — канонический формат
методологии, читаемый и существующими `/sdlc-*` скиллами Claude Code.

## Зачем

Методология до этого жила в двух видах, и оба неудобны: набор markdown-скиллов в терминале
(не видно, какой промпт ушёл и что агент собирается записать) и 18-блочный пайплайн поверх
большой Java-платформы (чтобы прогнать один виток, поднимается всё). Это середина.

## Что видно на каждом шаге

1. **Полный промпт** — системный блок (тело этапа из `SKILL.md` + adapter), схемы
   инструментов и пользовательское сообщение, с правкой перед отправкой.
2. **Затронутые файлы** — вызов инструмента перехватывается до исполнения: путь, unified
   diff «текущее ↔ предлагаемое», кнопки одобрить / отклонить / править аргументы.
3. **Ответ модели и артефакт этапа** — с подсветкой незаполненных плейсхолдеров `‹…›`.
4. **Стоимость, токены, время** — за этап и за виток, с указанием маршрута.

## Два флоу, одна политика

| Флоу | Цикл | Модели | Оплата |
|---|---|---|---|
| `sdk` | `@anthropic-ai/claude-agent-sdk` | Claude | Max-подписка |
| `loop` | собственный цикл tool-use | Ollama / vLLM / LM Studio / OpenRouter | локально бесплатно |

Переключение — **профилем целиком** (`claude` / `local`), внутри профиля модель настраивается
на каждом этапе. Флоу выводится из провайдера.

Чтобы флоу не разъехались, оба приводят вызов инструмента к одной форме (`NormalizedCall`)
**прежде**, чем его увидят политика доступа и UI; `pathScope` / `denyList` / `planScope` —
чистые функции без I/O, общие для обоих; conformance-тест роняет сборку при расхождении.

## Правило рецензента

Виток не стартует, если модель этапа `verify` не строго сильнее модели этапа `chunk`.
«Ревью независимым агентом» входит в минимальную пятёрку гейтов, у которой по методологии
нет переключателя — тихо понизить рецензента нельзя. Санкционированный выход один:
смешанный профиль, где `verify` идёт на более сильном маршруте.

## Запуск

```bash
npm install
npm run dev          # сервер :8030 + UI
npm test             # юнит-тесты политики и профилей
npm run typecheck
```

Конфигурация — в `config/`: `runner.json` (пути к эталону методологии и скиллам),
`models.json` (реестр моделей с рангами), `projects/*.json` (корень проекта, профили, бюджет).
