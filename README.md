# Agent-SDLC Runner

Тонкий сервис под один виток методологии [Agent-SDLC](https://github.com/): семь этапов
(`ЦЕЛЬ → РАЗВЕДКА → ВОПРОСЫ → ПЛАН → CHUNK → ВЕРИФИКАЦИЯ → COMMIT`) с видимыми запросами
к модели, одобрением записи файлов до её применения и учётом стоимости.

Артефакты витка пишутся в `.sdlc/<slug>/` целевого проекта — канонический формат
методологии, читаемый и существующими `/sdlc-*` скиллами Claude Code.

## Зачем

Методология до этого жила в двух видах, и оба неудобны: набор markdown-скиллов в терминале
(не видно, какой промпт ушёл и что агент собирается записать) и 18-блочный пайплайн поверх
большой Java-платформы (чтобы прогнать один виток, поднимается всё). Это середина.

## Что видно на каждом шаге

1. **Полный промпт** — системный блок (тело этапа из `SKILL.md` + adapter), схемы
   инструментов и пользовательское сообщение, с правкой перед отправкой.
2. **Затронутые файлы** — вызов инструмента перехватывается до исполнения: путь, unified
   diff «текущее ↔ предлагаемое», кнопки одобрить / отклонить / править аргументы.
3. **Ответ модели и артефакт этапа** — с подсветкой незаполненных плейсхолдеров `‹…›`.
4. **Стоимость, токены, время** — за этап и за виток, с указанием маршрута.

## Два флоу, одна политика

| Флоу | Цикл | Модели | Оплата |
|---|---|---|---|
| `sdk` | `@anthropic-ai/claude-agent-sdk` | Claude | Max-подписка |
| `loop` | собственный цикл tool-use | Ollama / vLLM / LM Studio / OpenRouter | локально бесплатно |

Переключение — **профилем целиком** (`claude` / `local`), внутри профиля модель настраивается
на каждом этапе. Флоу выводится из провайдера.

Чтобы флоу не разъехались, оба приводят вызов инструмента к одной форме (`NormalizedCall`)
**прежде**, чем его увидят политика доступа и UI; `pathScope` / `denyList` / `planScope` —
чистые функции без I/O, общие для обоих. Conformance-тест гоняет одну таблицу вызовов в
обеих формах и требует совпадения и формы, и вердикта политики.

Слабости локальных моделей учтены конструкцией, а не просьбой в промпте: повтор одного и
того же вызова получает замечание вместо результата и на третий раз обрывает этап;
сломанный JSON в аргументах объясняется модели, а не роняет прогон; вызов, написанный
текстом вместо `tool_calls`, распознаётся, если назван явно; результат каждого инструмента
режется по `maxToolResultBytes` — локальный контур живёт на 16K контекста.

Маршрут «Anthropic по ключу» намеренно не реализован: он оплачивается отдельно от подписки,
ради которой существует флоу `sdk`. Субагенты (`sdlc-locator`, `sdlc-reviewer`) во флоу
`loop` пока не запускаются — цикл говорит об этом вслух, потому что этап 6 без независимого
рецензента неполон.

## Гейты и вердикт

Автоматические гейты идут **перед** ревью и прогоняются рантаймом, а не по просьбе в
промпте. Набор берётся из `.sdlc/gates.md` проекта: где стоит команда — выполняется она,
где проза — встроенная реализация (сборка, тесты, scope, анти-обход тест-гейта, секреты,
предусловия публикации; порт выстраданных проверок из `agent-sdlc.yaml` платформы
AI-Workflow). Набор без любой строки обязательной пятёрки останавливает виток на старте.

Вердикт считает код по таблице методологии — четырнадцать условий, из которых любое роняет
результат. `⏭` снимается только строкой неприменимости с именем человека; при расхождении
отчёта рецензента с фактическим прогоном побеждает прогон. Поэтому слабая модель может
ошибиться в статусе, но не может выдать ложный зелёный.

## Правило рецензента

Виток не стартует, если модель этапа `verify` не строго сильнее модели этапа `chunk`.
«Ревью независимым агентом» входит в минимальную пятёрку гейтов, у которой по методологии
нет переключателя — тихо понизить рецензента нельзя. Санкционированный выход один:
смешанный профиль, где `verify` идёт на более сильном маршруте.

## Запуск

```bash
npm install
npm run dev          # сервер :8030 + UI
npm test             # юнит-тесты: политика, артефакты, гейты, вердикт, промпт
npm run typecheck
```

Конфигурация — в `config/`: `runner.json` (пути к эталону методологии и скиллам),
`models.json` (реестр моделей с рангами), `projects/*.json` (корень проекта, профили, бюджет).

## Состояние

В работе.

Готово: политика доступа с портом лексера shell-редиректов, профили и правило рецензента,
артефакты и машина витка, сборка промпта из `SKILL.md` эталона, оба флоу — `sdk` через
Agent SDK и `loop` со своим циклом tool-use и шестью инструментами, сервер и UI с
одобрением записи, гейты и вердикт.

Дальше: субагенты во флоу `loop`, калибровка гейтов посевом, редактор профилей в интерфейсе
(сейчас карта «этап → модель» правится в `config/projects/*.json`).

Сквозной виток на живом репозитории пока не прогонялся: код собирается и покрыт юнит-тестами,
но поведение под живой моделью не проверено.
