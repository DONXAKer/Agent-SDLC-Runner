# Диагностика модели перед серией задач

Команда запускает существующий preflight один раз, затем выполняет изолированные кейсы
из `bench/diagnostics/cases.json`. Каждый повтор получает отдельный результат. Кейсы без
проверенного входного снимка записываются как недоступные и не считаются ошибками модели.

```powershell
npm run bench:matrix
npm run bench:diagnose -- --model ollama:qwen3:8b-ctx16k
npm run bench:diagnose -- --model ollama:qwen3:8b-ctx16k --case V01 --repeat 5
npm run bench:diagnose -- --model ollama:qwen3:8b-ctx16k --compare bench/results/diagnostics-previous.json
```

По умолчанию запускается пять повторов каждого доступного кейса; допустимы 1–20 повторов.
`--stage-timeout` задаёт лимит одного запуска в минутах. Отчёты JSON и Markdown сохраняются
в `bench/results/`. Отчёт привязан к git revision, исходникам, модели, её конфигурации,
общему конфигу и входам каждого запуска.

Механические данные результата показывают завершение этапа, таймауты, трение рантайма и
прохождение посева. Они не определяют смысловую корректность. Проверяй артефакты по рубрике
кейса; сравнивай запуски с одинаковыми входами и меняй по одному параметру за раз. Preflight
сначала проверяет среду и конфигурацию; если он завершается с ошибкой, модельные кейсы не
стартуют.

Покрытие входов можно проверить без вызова модели командой `npm run bench:matrix`. На момент
добавления команды подготовлены 7 из 15 входов; остальные остаются явно недоступными до
появления валидных снимков.
## Перед сериями локальных моделей

Сначала проверь доступность Ollama и LM Studio, затем для каждой доступной уникальной локальной модели запусти `powershell -NoProfile -ExecutionPolicy Bypass -File bench/run-local-diagnostics.ps1 -Repeat 1`; отдельный профиль запускается командой `npm run bench:diagnose -- --model <id>`. Полный прогон использует пять повторов каждого доступного кейса; для первичного инвентарного прохода по большому набору установленных конфигураций допустим `--repeat 1`. Сопоставляй идентификаторы с `config/models.json` и пропускай облачные провайдеры. Проверка недоступных входов не считается ошибкой модели. Каждый результат сохраняется в `bench/results/`; серия начинается после разбора preflight и диагностических исходов.
