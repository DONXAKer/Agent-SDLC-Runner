# Эксперимент с выбором патча Chunk

Режим выключен по умолчанию. В профиле проекта:

```json
"chunkSelection": {
  "candidates": 2,
  "judgeModel": "<id локальной модели>",
  "candidateTimeoutMs": 60000
}
```

Без judgeModel используется модель Chunk. Допустимы 2–3 кандидата, локальный loop
и одна валюта бюджета. Таймаут одного кандидата по умолчанию 60 секунд: все файлы,
чтения и адресные ремонты входят в этот лимит. Общий таймаут этапа действует на весь
процесс, включая судью. Исчерпание лимита останавливает группу.

Арбитраж требует законченной разведки: адресованное чтение возможно только для
зафиксированных файлов группы, уже исследованных источников и рабочего контекста.
Запрос нового источника или поиска по проекту возвращает задачу на Explore.
Это сохраняет одинаковый вход кандидатов и проверяемую свежесть оснований.
В обычном guided без арбитража поведение чтения и поиска не меняется.

CLI стенда:

```powershell
node bench/src/cli.ts --all --task <task-id> --model <generator-id> --execution-mode guided --guided-engine-version 4 --chunk-candidates 2 --chunk-judge <judge-id> --chunk-candidate-seconds 60
```

Baseline запускается без `--chunk-*`. Guided можно продолжать со снимка того же
режима и версии движка; CLI проверяет их до вызова модели. Маршрут генератора
и остальных этапов сохраняется; отдельный судья задаётся явно. Jev/Nimble не подключены.

## Поведение

- Кандидат — полный патч группы зависимых файлов. `draftPerFile` собирает каждый
  вариант без промежуточных записей. При split части остаются в описании группы,
  а эксперимент собирает и применяет согласованный патч всей группы.
- Между кандидатами сбрасываются черновики, контекст и диагностика ремонта.
  Recovery имеет отдельные ключи раунда и кандидата. Повторных запусков всего
  GuidedExecutor нет: он сохраняет обычный жизненный цикл work item и WAL.
- Схемы, разрешённые операции, цели, символы и simulateOps проверяются обычным
  кодом. Неверный вариант получает адресный ремонт своего кандидата; если все
  варианты не подготовлены в лимите, группа останавливается.
- Одинаковые нормализованные after-images объединяются. Судья получает требования,
  карточки плана, наблюдавшиеся исходники и before/after вариантов. Симуляция не
  объявляется успешным тестом. Переполнение контекста останавливает группу без
  скрытого обрезания оснований.
- Есть исходы select, reject_all, insufficient_evidence. Неизвестный ID, неполный
  JSON и смена выбора при обратном порядке останавливают группу. no_change также
  проходит судью и обычную проверку поведения.
- Перед оценкой и применением сверяются исходники и редакция входа. Выбранный
  патч повторно симулируется, проходит стандартные разрешения, WAL и полные гейты.
  Изменённые оператором аргументы требуют нового предложения. Внешние правки
  сохраняются при конфликте.
- Все запросы входят в общий бюджет Chunk. Для следующих групп резервируется
  минимум генерации и двух оценок; остаток текущей группы делится между кандидатами.
  Purpose оценок — review. Красная проверка создаёт новый раунд в остатке бюджета.

Аудит: `.sdlc/<slug>/.runner/chunk-selection/<uuid>.json` — группа, модели, хэш
входа, варианты, дубликаты, ошибки, ответы судьи, выбор, расход и результат гейтов.
Метка HTTP-трассы оценщика — chunkJudge. Языковые ограничения GuidedExecutor сохраняются.

## Проверка и измерение

`server/test/chunkSelection.test.ts` проверяет применение, несколько файлов и групп,
v4, дубликаты, no_change, неверные операции, порядок вариантов, отказ всех вариантов,
недостаток данных, неизвестный ID, внешние правки, политику, бюджеты, контекст,
таймаут и откат красной проверки.

```powershell
node tools/chunk-selection-pilot.ts
node tools/chunk-selection-pilot.ts --run --repeats 1
```

Без --run запросов нет. Пилот сравнивает один вариант, два с self-judge, два
с отдельным судьёй и один на отдельном маршруте. Генерируется реальный код;
поведение проверяется исполняемыми сценариями из benchmark-данных. Входы и общие
лимиты одинаковы. Manifest и ответы — `bench/results/chunk-selection-<timestamp>/`.
Это компонентная проверка; она не заменяет полную SDLC-приёмку и не подтверждает
статистическую прибавку качества по одному повтору.
