# Наблюдение выполнения и эксперименты guided v4

В разделе «Наблюдение → События» доступна лента операций с фильтрами по этапу,
пункту работы, попытке и тексту. Раскрытие события показывает фактические данные,
а кнопка связанных событий отбирает операцию и её передачи. Лента начинает с
последних 100 событий, хранит до 2000 и показывает последние 100 результатов
фильтра. История целиком доступна в JSON и автономном HTML-отчёте.

`GET /api/runs/:id/execution?cursor=0&limit=100` возвращает события, следующий
курсор, признак продолжения и сводку. Без cursor возвращается конец журнала.
Лимит — от 1 до 500. `execution.json` выгружает весь журнал со сводкой;
`flow.html` — существующий автономный HTML. Обновление интерфейса использует
события текущего websocket-подключения и резервный опрос раз в две секунды.

Источник данных — существующий `.runner/flow/<runId>/trace.ndjson`.
Событие `execution_operation` версии 1 содержит ID операции и родителя,
пункт работы, попытку, вид, начало/конец, статус, длительность и основание.
Запросы и ответы модели/инструмента связаны requestId и ID операции.
Детальные операции записываются исполнителем Chunk; у других этапов остаются
существующие события, передачи данных и модельный расход. Отсутствующие
операции исторических или иных исполнителей не реконструируются как факты.

Сводка вычисляет проверки, первую проверку каждого пункта в запуске этапа,
буквальное повторение отказа, откаты, прерванные операции, неполные контексты,
время до первого изменения и успешной проверки. Времена инструментов,
проверок и ожидания ответа человека могут пересекаться и не суммируются
в длительность прогона. Время до первого изменения отсчитывается от первого
записанного входа в этап. Бюджет guided виден в существующей панели прогона.

Учёт назначений берётся только из `model_work`: HTTP-снимки расход повторно
не начисляют. Неизвестное количество запросов и стоимость остаются null.
Вызовы вне executor учитываются как unclassified. При нескольких валютах
в одной категории сумма не вычисляется. Ошибка журнала помечает сводку неполной,
не меняя решения исполнителя. При открытии того же журнала новым процессом
незавершённые операции помечаются interrupted. Повреждённые строки архива
пропускаются с отметкой неполноты.

Логи локальные и содержат исходники/ответы, необходимые для разбора. HTTP
заголовки и ключи авторизации не передаются этому регистратору. Подробный
архив остаётся закрыт для модельного чтения существующей политикой flow.
Публичное объяснение модели не считается фактическим результатом проверки.

## Независимые настройки профиля

```json
{
  "guidedImprovements": {
    "consumerContext": true,
    "evidenceRepair": false
  }
}
```

Обе настройки выключены при отсутствии поля и требуют guided v4.
`consumerContext` добавляет прямых потребителей, найденных по буквальным
JS/TS import/from/require. Комментарии и строки не считаются импортами;
неоднозначное разрешение пути отмечается как неизвестное. Неисследованный
потребитель отмечается как missing; содержимое появляется после разрешённого
чтения. Динамические импорты, package aliases и другие языки не разрешаются
этим механизмом. Пакет сохраняет прежние ограничения размера и хэши свежести.

`evidenceRepair` разрешает ограниченную попытку ремонта реализации по
структурированному отказу вместо обязательной модельной классификации.
Поддержаны точные относительные TS-диагностики `file(line,column): error TS...`
и распознанные тестовые сообщения с actual/expected. Неизвестный формат,
диагностика вне разрешённых файлов или отсутствие исходного запроса требуют
возврата к исследованию. Ошибка среды не запускает ремонт. Существующие лимиты,
политика записи, проверки, свежесть исходников и откат сохраняются. Ни старые,
ни новые тестовые файлы не становятся целями этого ремонта. Провал теста
разрешает гипотезу исправления, но не объявляет тестовый oracle истинным.

Бенч-флаги: `--consumer-context`, `--evidence-repair`; выбранные значения
сохраняются в паспорте результата. Сравнение:

```
node tools/compare-guided-improvements.mjs
node tools/compare-guided-improvements.mjs --run
```

Серия фиксирует восемь задач, два повтора и три независимых режима; маршруты,
бюджеты и хэш исходников одинаковы. На этап отведено 5 минут, на прогон 10,
не более 3 попыток. Это предварительное сравнение; ранний отказ до Chunk
не свидетельствует о качестве его новых механизмов. Полная приёмка требует
handoff, вердикта, скрытых тестов, honesty и ограничения активного времени.
Ложный успех измеряется только при доступной независимой проверке.

## Проверка реализации — 2026-10-14

После последних исправлений: `npm test` — 3338 passed, 7 skipped, 0 failed;
`npm run typecheck` и `npm run build` прошли. Регрессии проверяют сохранение
связей позднего ответа с исходным этапом, повторную загрузку событий без
двойного учёта, прерывание и отказ журнала, ограничения контекста и ремонта,
защиту `__tests__/`, `specs/` и тестовых суффиксов, откат после отмены.

Сравнительная серия запущена в
[`guided-improvements-20261014075627935`](../bench/results/guided-improvements-20261014075627935/suite.json).
`suite.json` обновляется после каждого прогона; итоговый `report.md` создаётся
после всех 48. В каждом результате сохраняется `execution` со сводкой,
а в серии — признак `reachedChunk`. На момент запуска вывода о преимуществе
какого-либо режима нет.

Этот запуск показывает ограничение подготовки, а не эффективность ремонта.
