# Проверка решений и схема прогона

В `guided` каждый из семи этапов начинает с короткой проверки предварительного подхода.
Модель возвращает решение, основания, существенные пробелы и следующее действие.
Рантайм проверяет дословные цитаты по действительно показанным источникам. Продолжение
возможно при наличии оснований и отсутствии существенных пробелов для следующего действия.
На `explore` таким действием может быть исследование, а не готовый вывод о непрочитанном коде.

При конкретном пробеле доступны `read`, `search`, чтение входа по символам через `input`
и на этапе `ask` вопрос о недостающем бизнес-правиле. Файловые инструменты и вопросы
проходят существующую политику и одобрения; `input` читает только уже разрешённый вход.
Большой вход показывается явными фрагментами, скрытую часть можно дочитать, а цитаты
проверяются только по действительно показанному тексту. Вопрос сохраняет исходный текст,
имеет два разных варианта и не может перекладывать обратимые инженерные детали на человека.
Полученные данные передаются обратно в проверку, а подтверждённый или изменённый подход
с дословными основаниями и адресами источников — исполнителю этапа, включая исполнителей
с отдельными JSON-промптами. Повтор без нового входа останавливает этап. Дополнительные
обращения расходуют его общий лимит, оставляя хотя бы одно обращение для исполнения;
также действуют текущие ограничения времени, контекста и стоимости.

Новое бизнес-правило на `chunk`, `verify` или `handoff` блокирует продолжение с указанием
вернуться к `ask` и подтверждению плана. Автоматически согласованные требования не меняются.
Журнал `guided.decisionChecks` в API содержит основания, наблюдения, блокеры и признак
изменения текста решения между проверками. Проверка наличия цитаты подтверждает источник,
но не доказывает логическую правильность вывода: итог по-прежнему проверяют гейты и приёмка.
В обычном режиме проверка решений не включается, но HTML-схема сохраняется.
Архивы текущей и прежних сессий закрыты для `verify` и инструментального `sdlc-claims`,
чтобы копии промптов и прежних отчётов не обходили независимость проверки. Человек
по-прежнему открывает эти архивы через API или напрямую.
Пропуск условного этапа, например `ask` без открытых вопросов, получает краткую запись
проверенных предусловий от рантайма без обращения к модели (`checkedBy: runtime`).

## HTML для каждого прогона

В шапке живого прогона есть ссылка **«Схема прогона»**. Она открывает автономный HTML
через `GET /api/runs/:id/flow.html`.
Ссылка также доступна в карточках истории и стенда через
`GET /api/dashboard/:source/:project/:slug/flow.html`; старый архив при необходимости
преобразуется из ленты событий с явной пометкой отсутствующих данных. Каждый вход в этап,
включая повторные попытки, показан отдельно. Доступны поиск по данным/путям/requestId, фильтры решений, модели,
инструментов, файлов и проблем, а также раскрытие переданных данных.

Сохраняются:

- подготовленные промпты, решения политики, вопросы/ответы человека и результаты инструментов;
- фактические тела HTTP-запросов и ответы OpenAI-compatible провайдеров, включая повторы,
  смену параметров и ошибки сети, без HTTP-заголовков;
- первоначальные решения, новые основания и пересмотры;
- снимки входных/выходных артефактов и файлов плана, а также других одобренных целей записи;
  изменения между снимками, их хэши и сравнение текста до/после.

Порядок карточек отражает порядок записи; параллельные вызовы связаны по `requestId`.
Изменение файла после инструмента является наблюдением, а не доказательством авторства:
внешняя правка между снимками тоже видна. Снимки текста ограничены 128 KB; для файлов
больше 1 MB сохраняются только размер и время записи с явной пометкой. Изменения через
shell за пределами известных файлов могут не иметь снимков, но сама команда и её результат
остаются в трассе. У SDK доступны события/промпты и снимки, но не внутренние HTTP-запросы
харнесса. Пустоты отчёта не заполняются выдуманными данными.

Файлы в рабочей копии:

```text
.sdlc/<slug>/.runner/flow/<runId>/trace.ndjson
.sdlc/<slug>/.runner/flow/<runId>/index.html
.sdlc/<slug>/.runner/flow.html               # последняя сохранённая схема
```

HTML обновляется после каждого этапа, включая остановку/отмену. Бенчмарк копирует HTML и
подробные трассы в `bench/traces/<slug>/` до удаления рабочей копии. Отчёт работает без
сервера, интернета и внешних библиотек. Сырые данные лежат рядом, чтобы HTML можно было
пересобрать после прерванного процесса:

```powershell
npm.cmd run flow:html -- --trace path/to/trace.ndjson --out flow.html --slug my-run
```

Для старых прогонов можно импортировать сохранённую ленту событий:

```powershell
npm.cmd run flow:html -- --events bench/traces/<slug>/events.ndjson --out flow.html
```

В таком отчёте отмечено, что старые обмены могли быть обрезаны, а полные HTTP-запросы и
снимки файлов не записывались. Улучшение качества решений нужно отдельно измерять
парными прогонами на удержанных задачах: исправленные ошибки, испорченные правильные
решения, блокировки и добавленное время. Автоматические тесты проверяют протокол и
ограничения, а не обещают улучшение конкретной модели.
