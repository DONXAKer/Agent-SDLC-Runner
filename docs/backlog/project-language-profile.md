# Языковой профиль проекта

**Пункт плана:** 3 · **Категория:** мультиязычность и паттерны
**Слаг витка:** project-language-profile

## Зачем
`ProjectConfig` (`server/src/config/schema.ts:61`) знает про проект пять вещей: `name`,
`projectRoot`, `activeProfile`, `maxBudgetUsd`, `profiles`. Про то, на чём проект написан и
чем он собирается, — ничего. Единственная истина об этом — автодетект
`detectBuildSystem` по составу одного каталога.

Каталог этот выбирает `moduleDirFromPlan` (`server/src/gates/builtin/logic.ts:96`): идёт от
первого файла плана вверх до первого каталога с манифестом и возвращает **один** модуль.
Комментарий там честно фиксирует, зачем так сделано (алфавитный перебор брал случайный
модуль и зеленел), но допущение остаётся: один виток — один модуль. Моно-репо, где план
трогает `api/` на Go и `web/` на TypeScript, получает сборку и тесты только первого из них,
а второй молча не проверяется — и вердикт при этом зелёный.

Второй разрыв: проект не может сказать «здесь build — `make build`, а не то, что ты
угадал». Переопределить команду сегодня можно только через `.sdlc/gates.md` целевого
проекта (`parseCommand` в `server/src/gates/gatesFile.ts:101`), то есть в файле, который
живёт в чужом репозитории и правится человеком там — конфигурация рантайма про это не
знает.

## Что сделать
1. Добавить в `ProjectConfig` необязательное поле `languages` (или `modules`) — список
   описаний: путь модуля относительно `projectRoot`, экосистема, необязательные
   переопределения `build`/`test`/`lint`.
2. Разбирать и валидировать это поле в `loadConfig` (`server/src/config/load.ts:68`) рядом с
   существующими проверками `name`/`projectRoot`: несуществующий путь модуля и неизвестное
   имя экосистемы — ошибка загрузки, а не молчание. JSON читается без схемы, поэтому
   проверка обязана быть явной (см. комментарий про `LIMIT_DEFAULTS`, `load.ts:27-33`).
3. Провести значение до `GateContext` (`server/src/gates/builtin/index.ts:33`) — сегодня в
   контексте есть только `projectRoot`, `planFiles`, `baseline`, `timeoutMs`, `signal`.
   Контекст собирается в `runGates` (`server/src/gates/run.ts:105`) и приходит из
   `Run.runVerifyGates`.
4. Приоритет источников зафиксировать явно и одинаково для всех гейтов: команда из
   `.sdlc/gates.md` > профиль проекта > автодетект. Это продолжение уже действующего правила
   `run.ts:56` («проект, назвавший свою команду, знает про себя больше, чем детект»).
5. Автодетект оставить fallback'ом: пустое поле `languages` = сегодняшнее поведение, ни один
   существующий конфиг не ломается.
6. Обновить `config/projects/example.json` — показать поле с комментарием-ключом `"// …"`
   (принятая в проекте форма).
7. Тесты: `server/test/profiles.test.ts` или `gates.test.ts` — приоритет источников и отказ
   загрузки на неверном описании модуля.

## Файлы
- `server/src/config/schema.ts` — поле `languages`/`modules` в `ProjectConfig`
- `server/src/config/load.ts` — разбор и валидация нового поля
- `server/src/gates/builtin/index.ts` — `GateContext` получает профиль; `resolveModule` учитывает его прежде автодетекта
- `server/src/gates/run.ts` — прокидывание профиля в контекст
- `config/projects/example.json` — пример заполнения
- `server/test/profiles.test.ts` — валидация и приоритет

## Приёмочный лист
- [ ] Проект без поля `languages` ведёт себя ровно как сегодня (тест на существующем сценарии).
- [ ] Заданная в профиле команда `build` побеждает автодетект, а команда из `.sdlc/gates.md` побеждает профиль — три случая покрыты тестами.
- [ ] Модуль с несуществующим путём или неизвестной экосистемой роняет `loadConfig` с сообщением, называющим проект и поле.
- [ ] `config/projects/example.json` содержит пример и остаётся валидным JSON.
- [ ] Ограничение «один модуль на виток» либо снято, либо явно названо в карточке `gates-parallel-modules` как оставшийся долг — не замолчано.

## Риски и инварианты
- Профиль проекта — конфигурация рантайма, а не витка. Команды оттуда исполняются `runShell`, то есть проходят `checkBash`/`DenyList` (`server/src/gates/shell.ts:56`) — ослаблять этот пол под «свои» команды нельзя, он «конфигом не ослабляется» (CLAUDE.md).
- `exactOptionalPropertyTypes` включён: новое необязательное поле требует идиомы `...(x === undefined ? {} : { x })`, а не `x`.
- `projects/*.local.json` в `.gitignore` — примеры и документация правятся только в `example.json`.
- Соблазн «пусть профиль задаёт статус гейта» — запрещён: статус даёт прогон, конфиг задаёт только чем прогонять.

## Зависимости
`gates-ecosystem-registry` — имена экосистем в конфиге должны ссылаться на реестр, иначе
поле `languages` станет третьим независимым знанием о языках.
