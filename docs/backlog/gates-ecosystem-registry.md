# Плагинная точка расширения экосистем

**Пункт плана:** 1 · **Категория:** мультиязычность и паттерны
**Слаг витка:** gates-ecosystem-registry

## Зачем
Сегодня знание об экосистемах размазано по двум файлам и записано в виде закрытых
конструкций. `detectBuildSystem` (`server/src/gates/builtin/logic.ts:30`) — лестница
`if (has('gradlew')) … if (has('pom.xml')) … if (has('go.mod')) …`, возвращающая
`BuildSystem { build, test, needsNodeModules }`. Рядом, в том же файле, лежат независимые
от неё закрытые списки: `CODE_EXT`, `DISABLE_MARKERS`, `TEST_DECL`, `TEST_FILE`, `COMMENT`,
`JUNK`. Ни одна из этих вещей не знает про остальные, хотя все они отвечают на один вопрос
— «что за экосистема перед нами».

Следствия конкретны:
- добавление языка = правка ядра гейтов, то есть файла, который читают обе обязательные
  строки набора («Сборка», «Тесты») и анти-обходной гейт; цена ошибки — молчаливо
  зазеленевший или вечно красный обязательный гейт;
- поле `needsNodeModules` в `BuildSystem` названо по npm, но проверяется в
  `server/src/gates/builtin/index.ts` для любой системы (`buildGate`, `testGate`) — для
  Python/Go/Rust нужного эквивалента («нет venv», «нет vendor») выразить нечем, и «нечем
  собирать» неотличимо от «код не собирается»;
- `syntaxOnly` (`index.ts:146`) прибит к `node --check` и константе `JS_FILE` — запасной
  ветки для не-JS не существует в принципе.

## Что сделать
1. Завести каталог `server/src/gates/ecosystems/` и тип описания экосистемы: имя, предикат
   детекта по составу каталога (плюс, где нужно, содержимое манифеста), команды
   `build`/`test`, признак «зависимости не установлены» с собственным предикатом каталога
   (`node_modules`, `.venv`, `vendor`, `target` — что именно, решает экосистема), расширения
   исходников.
2. Перенести каждую ветку `detectBuildSystem` в отдельный файл (`node.ts`, `gradle.ts`,
   `maven.ts`, `go.ts`, `rust.ts`, `python.ts`) без изменения поведения — те же команды,
   тот же порядок.
3. Порядок детекта сделать явным данным (список в `ecosystems/index.ts`), а не порядком
   строк в функции: комментарий в `logic.ts:22-29` объясняет, почему `package.json` идёт
   перед `tsconfig.json` — это правило обязано пережить переезд и остаться читаемым.
4. `detectBuildSystem` сохранить как тонкую обёртку над реестром, чтобы вызывающие
   (`resolveModule`, `buildGate`, `testGate` в `index.ts`) не менялись в этом витке.
5. Заменить `needsNodeModules: boolean` на предикат «зависимости на месте» у экосистемы;
   обновить обе точки использования в `index.ts` (строки ~234 и ~278) и текст `⏭`, чтобы он
   называл каталог, которого не хватило, а не всегда `node_modules`.
6. Расширить `server/test/gates.test.ts`: таблица «состав каталога → ожидаемая экосистема и
   команды», прогоняемая по реестру, а не по списку `if`.

## Файлы
- `server/src/gates/ecosystems/*.ts` — новые файлы, по одному на экосистему (сейчас каталога нет)
- `server/src/gates/ecosystems/index.ts` — реестр и порядок детекта
- `server/src/gates/builtin/logic.ts` — `detectBuildSystem` становится обёрткой; тип `BuildSystem` теряет `needsNodeModules` в пользу предиката
- `server/src/gates/builtin/index.ts` — `resolveModule`, `buildGate`, `testGate`: проверка установленных зависимостей через экосистему
- `server/test/gates.test.ts` — табличные тесты детекта

## Приёмочный лист
- [ ] Каждая существующая ветка `detectBuildSystem` даёт ровно те же `build`/`test`, что и до правки. Список брать из кода, а не отсюда, и покрыть целиком: gradlew, build.gradle(.kts), pom.xml, go.mod, Cargo.toml, package.json со скриптами, package.json без `build`/`test` (`npm run build --if-present`, `test: null`), только `tsconfig.json`, python по любому из `pyproject.toml`/`setup.py`/`pytest.ini`/`setup.cfg`. Именно две последние ветки легко пропустить — а регресс в них молча меняет команду обязательного гейта «Сборка».
- [ ] Приоритет `package.json` над `tsconfig.json` выражен данными реестра и покрыт тестом.
- [ ] Новая экосистема добавляется созданием одного файла в `ecosystems/` и одной строкой в списке порядка; ни `logic.ts`, ни `builtin/index.ts` при этом не меняются — проверяется чтением диффа демонстрационного добавления.
- [ ] Сообщение `⏭` про неустановленные зависимости называет фактически искомый каталог экосистемы.
- [ ] `npm run typecheck` и `npm test` зелёные (запускает человек — виток на dev-сервере трогать нельзя).

## Риски и инварианты
- «Сборка» и «Тесты» — строки обязательного минимума (`MINIMUM` в `server/src/gates/gatesFile.ts`). Регресс в детекте роняет каждый виток на всех проектах, а не только на новых языках.
- Инвариант честности статусов: `⏭` не должен превращаться в `✅` (комментарии в `builtin/index.ts:196-208`). Реестр не даёт права упростить «нечем собрать» до зелёного.
- `logic.ts` по построению без I/O — «здесь нет ни файловой системы, ни git». Предикаты экосистем обязаны получать состав каталога снаружи (как сейчас `dirEntries` в `index.ts`), а не читать диск сами.
- Комментарии, фиксирующие пойманные дефекты (приоритет манифестов, `parentOf('.')`), переносить вместе с кодом, а не выбрасывать.
