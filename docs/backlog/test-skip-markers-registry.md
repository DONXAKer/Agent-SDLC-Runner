# Маркеры отключения тестов — в данные, а не в код

**Пункт плана:** 5 · **Категория:** мультиязычность и паттерны
**Слаг витка:** test-skip-markers-registry

## Зачем
Анти-обходной тест-гейт держится на четырёх закрытых регулярках в
`server/src/gates/builtin/logic.ts`:

- `CODE_EXT` (строка 174) — что считать кодом;
- `DISABLE_MARKERS` (строка 184) — `@Disabled|@Ignore|@pytest\.mark\.skip|\bit\.skip\(|…`;
- `TEST_DECL` (строка 187) — `@Test|def test_|func Test|\bit\(|…`;
- `TEST_FILE` (строка 189) — как выглядит путь тестового файла.

Все четыре читает `invariantViolations` (строка 218) — единственный поставщик находок для
гейтов «Анти-обход тест-гейта» (строка минимума) и «Секреты в diff». Списки перечисляют
языки вперемешку, и добавление экосистемы означает правку четырёх регулярок в одном файле,
причём с риском не заметить, что для нового языка есть маркер отключения, но нет формы
объявления теста — тогда `tests-removed` считает нетто-убыль по языку, деклараций которого
не видит, и гейт минимума молча ничего не проверяет.

Отдельная опасность — `\b`. `DISABLE_MARKERS` и `TEST_DECL` используют границу слова, а в
JS она считается по ASCII. Пока маркеры латинские, это работает; любой маркер или имя с
кириллицей (комментарий-аннотация, кастомный хелпер `тест(`) через `\b` не найдётся. В
`gatesFile.ts:78-82` этот класс ошибки уже стоил того, что вся обязательная пятёрка молча
числилась выключенной.

## Что сделать
1. Перенести в описание экосистемы (`server/src/gates/ecosystems/*.ts` из карточки
   `gates-ecosystem-registry`) четыре набора: расширения исходников, маркеры отключения
   теста, формы объявления теста, форма имени тестового файла. Плюс форму комментария —
   сейчас `COMMENT` (строка 182) один на все языки и не знает про `<!--`, `%`, `;`.
2. Хранить их как списки строк/фрагментов, а не как одну сшитую регулярку: список — данные,
   его видно в дампе и можно проверить тестом поштучно.
3. Собирать рабочие регулярки из реестра один раз при старте, а не на каждый вызов
   `invariantViolations` (её зовут через `diffViolations` на каждый прогон гейтов).
4. `\b` при сборке не использовать. Границы задавать явными классами по образцу
   `gatesFile.ts` (`/^да([\s.,;:—–()-]|$)/`), а спецсимволы фрагментов экранировать при
   сборке, чтобы автор описания экосистемы не обязан был помнить про `.` и `(`.
5. Сохранить деление находок по `kind` (`test-disabled`, `test-file-deleted`,
   `tests-removed`, `secret-in-diff`): гейты фильтруют по нему в `makeDiffGate`
   (`builtin/index.ts:411`), и склейка видов сделала бы статусы неразличимыми.
6. `SECRET` (строка 192) оставить общей: она про diff целиком, а не про язык — комментарий
   на строке 260 объясняет, почему.
7. Тесты в `server/test/gates.test.ts`: по одному diff-примеру на язык для каждого вида
   находки, плюс негативный тест на закомментированную строку.

## Файлы

- `server/src/gates/builtin/logic.ts` — `CODE_EXT`, `DISABLE_MARKERS`, `TEST_DECL`, `TEST_FILE`, `COMMENT` собираются из реестра; `invariantViolations` не меняет контракта

## Риски и инварианты
- «Анти-обход тест-гейта» — строка минимума. Ослабление регулярки = ложный зелёный на витке, где исполнитель заглушил тест; это ровно тот класс, ради которого гейт заведён.
- Ужесточение так же вредно: `COMMENT` появился потому, что гейт срабатывал на собственных правилах, процитированных в документации (комментарий на строке 177-180). Проверять на реальном diff этого репозитория.
- `\b` по кириллице — прямое предупреждение CLAUDE.md, уже стоившее молчаливого отключения всей пятёрки.
- `logic.ts` остаётся без I/O.
