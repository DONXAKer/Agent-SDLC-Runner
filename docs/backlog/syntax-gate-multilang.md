# Мультиязычный syntaxOnly

**Пункт плана:** 2 · **Категория:** мультиязычность и паттерны
**Слаг витка:** syntax-gate-multilang

## Зачем
`syntaxOnly` (`server/src/gates/builtin/index.ts:146`) — запасная ветка гейта «Сборка» для
случая «собрать нечем». Она фильтрует изменённые файлы константой `JS_FILE`
(`/\.(js|cjs|mjs)$/i`) и запускает `node --check` через `nodeCheck` пачками по
`NODE_CHECK_PARALLEL` с собственным потолком `NODE_CHECK_TIMEOUT_MS`.

Для проекта на Python, Go, Ruby или PHP без обнаруженной build-системы `changed` после
фильтра пуст, и гейт печатает «проверять синтаксисом тоже нечего» — формально честно, но
фактически это значит, что на не-JS проекте запасной ветки нет вообще: файл, который не
парсится, доезжает до ревью. Смысл ветки (комментарий на `index.ts:136-144` — «нечем
собрать не равно нечего проверить») на всех языках, кроме JS, не выполняется.

## Что сделать
1. Ввести таблицу «расширение → чекер»: `.py` → `python3 -m py_compile <file>`, `.go` →
   `gofmt -e <file>` (парсер, не форматирование) и/или `go vet ./...` на модуле, `.rb` →
   `ruby -c <file>`, `.php` → `php -l <file>`. Таблица живёт в реестре экосистем из карточки
   `gates-ecosystem-registry`, а не отдельным словарём в `index.ts`.
2. Языки брать из уже существующего списка `CODE_EXT` (`server/src/gates/builtin/logic.ts:174`)
   — второй список расширений в кодовой базе заводить нельзя, иначе анти-обходной гейт и
   синтакс-гейт разойдутся в том, что считают кодом.
3. Каждый чекер запускать по образцу `nodeCheck`: путь **аргументом**, а не текстом команды;
   собственный таймаут на файл; `spawn` с `signal`. Батчить существующим `inBatches`
   (`index.ts:123`) — новый пул не писать.
4. Отсутствие интерпретатора (`ENOENT` при spawn) отличать от синтаксической ошибки:
   «python3 не найден» — это `⏭` с честной формулировкой, а не `❌`. Сегодня для JS такой
   развилки нет, потому что `node` — это `process.execPath`.
5. В итоговой строке разложить счётчики по языкам: сколько проверено, сколько пропущено и
   почему (нет интерпретатора / ESM-JSX-исключение, которое остаётся только у JS).
6. Статус ветки не менять: максимум остаётся `⏭` («синтаксис — не сборка», комментарий
   `index.ts:196-208`).
7. Тесты в `server/test/gates.test.ts` — на разбор исходов и счётчиков (на фиктивных
   результатах чекеров), а не на наличие интерпретаторов на машине CI.

## Файлы
- `server/src/gates/builtin/index.ts` — `syntaxOnly` работает по таблице чекеров, `JS_FILE` уходит в описание JS-экосистемы; `nodeCheck` обобщается до «запусти чекер на файле»
- `server/src/gates/ecosystems/*.ts` — команда синтакс-проверки в описании экосистемы
- `server/src/gates/builtin/logic.ts` — `CODE_EXT` становится источником расширений (экспорт/переиспользование)
- `server/test/gates.test.ts` — исходы и счётчики

## Приёмочный лист
- [ ] Второго списка расширений исходников в кодовой базе нет: grep по `\\.(java|kt|` находит одно определение.
- [ ] Файл с заведомо битым синтаксисом на каждом поддержанном языке даёт `❌` с именем файла и текстом ошибки чекера.
- [ ] Отсутствующий интерпретатор даёт `⏭` со словами «не найден», а не `❌`.
- [ ] Ни один сценарий этой ветки не возвращает `✅` — проверяется чтением кода и тестом.
- [ ] Пути передаются аргументами `spawn`; в строку команды не вклеиваются (чтение диффа).
- [ ] Число одновременно живущих процессов ограничено `inBatches`; второго механизма параллельности не появилось.

## Риски и инварианты
- `gofmt -l` печатает имена файлов, отличающихся форматированием, и молчит про синтаксис — это гейт стиля, а не синтаксиса. Для парсинга нужен `gofmt -e` (или `go build`), иначе гейт краснеет на корректном коде.
- `python -m py_compile` пишет `.pyc` рядом с исходником (без `PYTHONDONTWRITEBYTECODE=1`), а `__pycache__/` попадёт в diff и уронит scope-гейт («Scope: файлы вне плана») и `publishProblems`, где `__pycache__` уже числится мусором. Писать байт-код гейту нельзя.
- `php -l` и `ruby -c` выполняют код на уровне директив (`__halt_compiler`, `BEGIN {}`) — держать таймаут на файл обязательно.
- Инвариант честности: «гейт, который врёт, приучает игнорировать себя» (шапка `builtin/index.ts`).
