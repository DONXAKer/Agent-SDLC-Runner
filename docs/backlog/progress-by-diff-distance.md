# Прогресс по diff-дистанции

**Пункт плана:** 13 · **Категория:** качество за меньше итераций
**Слаг витка:** progress-by-diff-distance

## Зачем

`Run.detectNoProgress()` (`server/src/run/Run.ts`) сравнивает патч текущей попытки с патчем
предыдущей **дословно**:

```
return current.text.trim() === prev.text.trim();
```

Результат уходит в `VerdictInput.noProgress`, а `decideAction` (`server/src/verdict/verdict.ts`)
превращает его в `escalate` — «две попытки подряд дали один и тот же diff по существу, это
остановка, а не следующая попытка».

Комментарий у функции честно объясняет выбор: «по существу» отличалось бы от «побайтово»
только на шуме, и ложная эскалация дороже ложного продолжения. Но у дословного сравнения
есть цена, которую видно на практике: топтание на месте почти никогда не выглядит как
побайтово идентичный патч. Модель переставляет строки, меняет имя переменной, дописывает
комментарий — и детект молчит, пока не исчерпается `attemptBudget` (умолчание 3, читается
из строки «бюджет итераций» набора гейтов). Три полных прогона этапов 5 и 6 на локальном
контуре — это десятки минут и весь смысл этой пачки задач.

Метрика близости не отменяет дословного равенства, а достраивает его: равенство остаётся
безусловным сигналом, близость — сигналом «скорее всего топчемся», требующим решения
человека.

## Что сделать

1. Новый файл `server/src/run/diffDistance.ts` — чистая функция без I/O: два текста
   unified diff → доля общих hunks. Разбор по заголовкам `@@ … @@` и по заголовкам файлов
   `diff --git` / `+++`; сравнивать нормализованное тело hunk'а (без номеров строк, они
   съезжают от любой правки выше по файлу).
2. Метрика: доля hunks предыдущего патча, для которых в текущем нашёлся hunk с тем же телом,
   от общего числа. `1.0` — полное совпадение по существу, `0` — общего нет. Определить
   поведение на вырожденных входах явно: пустой патч, патч без единого `@@`, патч с одним
   hunk'ом.
3. `detectNoProgress()` оставить как есть (дословное равенство → `noProgress = true`) и
   добавить рядом расчёт близости. Порог — конфигурируемый, с умолчанием, не спрятанным в
   коде дважды.
4. Близость выше порога **не** должна сама по себе давать `escalate`: в `Verdict.reasons`
   она попадает как названный факт, а решение остаётся за оператором — ровно потому, что
   ложная эскалация дороже ложного продолжения, и это уже записано в коде.
5. Показать метрику в UI (`web/src/pages/RunPage.tsx`) числом и с обеими попытками, чтобы
   оператор мог глазами проверить утверждение «diff почти тот же».
6. Тесты на реальной форме патчей: перестановка hunks, сдвиг номеров строк от правки выше,
   переименование файла, добавление одного нового hunk к прежним.

## Приёмочный лист

- [ ] два побайтово одинаковых патча по-прежнему дают `noProgress = true` и `action = escalate` — поведение из `decideAction` не изменилось
- [ ] патч, отличающийся от предыдущего только съехавшими номерами строк в заголовках `@@`, даёт близость 1.0
- [ ] патч, где к прежним hunks добавлен один новый, даёт близость строго меньше 1.0
- [ ] высокая близость сама по себе не переводит `action` в `escalate` — проверено тестом
- [ ] мера — чистая функция двух строк, без чтения файлов; `Run` передаёт ей уже прочитанные патчи
- [ ] на первой попытке (`attempt < 2`) мера не считается и в UI не показывается как «0»

## Риски и инварианты

- **Ложная эскалация дороже ложного продолжения** — это записанное в `Run.ts` решение, и
  метрика не должна его молча переворачивать. Автоматический `escalate` по близости —
  именно такой переворот.
- **Артефакты попыток не перезаписываются** (`nextAttempt`): сравнение двух патчей —
  единственная механическая улика топтания, и любая оптимизация вида «хранить только
  последний патч» уничтожает и старый детект, и новый.
- **Шум против существа.** Порог, подобранный на одном витке, — предположение. Сквозной
  виток на живом репозитории ни разу не прогонялся, поэтому число должно быть настройкой с
  умолчанием, а не константой, вокруг которой построена логика.
- **Производительность.** Патчи бывают сотнями килобайт; `stages.ts` уже переводил проверки
  существования со чтения на `stat` именно из-за этого. Мера считается один раз на вердикт,
  а не на каждый запрос состояния.
