# Гейт-детектор переписанного хелпера

**Пункт плана:** 8 · **Категория:** мультиязычность и паттерны
**Слаг витка:** reuse-duplicate-helper-gate

## Зачем
«Не переписал ли хелпер, который уже есть в кодовой базе» — типовая находка ревью и
отдельный угол в глобальном чек-листе. Сегодня его закрывает только человек и субагент
`sdlc-reviewer` на этапе 6: среди встроенных гейтов (`BUILTIN`,
`server/src/gates/builtin/index.ts:495`) ничего похожего нет, а `invariantViolations`
(`server/src/gates/builtin/logic.ts:218`) смотрит на diff только на предмет отключённых
тестов, удалённых тестовых файлов и секретов.

Проверка ревьюером — самая дорогая из доступных (сильная модель, полный контекст) и самая
ненадёжная для этого класса: чтобы заметить дубль, рецензенту надо знать всю кодовую базу
целевого проекта, а он получает задачу, план, набор гейтов и diff. Дешёвая эвристика по
именам ловит частый случай (`formatDate`, `normalizePath`, `toPosix`) до ревью и стоит один
grep.

Сама кодовая база рантайма — иллюстрация цены: комментарии фиксируют, что копий
`normalizePlanPath` было две (`logic.ts:147-151`), определений плейсхолдера — четыре
(`gatesFile.ts:56-59`), а `gateKey` существовал в четырёх файлах в четырёх версиях
(`gatesFile.ts:202-209`). Каждая расходившаяся копия давала дефект.

## Что сделать
1. Извлечь из diff'а имена **добавленных** объявлений функций. Разбор diff'а уже есть —
   `diffLines` (`logic.ts:202`), экспортируется; брать её, а не писать второй парсер.
   Формы объявлений (`function x`, `def x`, `func x`, `fn x`, `const x = (`) — из реестра
   экосистем (`gates-ecosystem-registry`), туда же, где живут `TEST_DECL` и маркеры.
2. Отфильтровать шум: слишком короткие и слишком общие имена (`run`, `get`, `main`, `init`),
   методы классов, тестовые файлы, приватные обёртки в том же файле.
3. Искать одноимённые объявления в целевом проекте — за пределами файлов diff'а. Приоритет
   поиску отдать «общим» каталогам (`shared/`, `utils/`, `util/`, `common/`, `lib/`,
   `helpers/`), но не ограничиваться ими: `normalizePlanPath` в этом репозитории лежит в
   `server/src/policy/paths.ts`.
4. Исход — **не** `❌`. Находка эвристики не является нарушением: одноимённая функция в
   другом модуле бывает законной. Правильный исход — `⏭` со списком «в diff добавлена
   `formatDate`, одноимённое объявление уже есть в `src/utils/date.ts:42` — это переписанный
   хелпер?», требующий подписи человека о неприменимости. Так гейт не врёт и не блокирует.
5. Зарегистрировать в `BUILTIN` под именем строки набора (например «Дубли хелперов»), с
   «Где отчитывается: этап 6». В `MINIMUM` не добавлять.
6. Потолок на объём: поиск по большому чужому репозиторию — I/O на критическом пути этапа.
   Ограничить числом имён-кандидатов и уважать `ctx.signal` и `ctx.timeoutMs`, как остальные
   гейты.

## Файлы
- `server/src/gates/builtin/logic.ts` — чистая часть: извлечение имён из diff и фильтр шума (без I/O, как весь файл)
- `server/src/gates/builtin/index.ts` — гейт: поиск по дереву, формирование `⏭`, строка в `BUILTIN`
- `server/src/gates/ecosystems/*.ts` — формы объявления функций по языкам
- `server/test/gates.test.ts` — извлечение имён, фильтр шума, формирование исхода

## Приёмочный лист
- [ ] На diff'е, добавляющем функцию с именем, которое уже есть в проекте, гейт печатает обе локации (файл diff'а и найденный файл со строкой).
- [ ] На diff'е без дублей гейт даёт `✅` и не читает лишнего.
- [ ] Гейт никогда не возвращает `❌`: эвристика не блокирует виток — проверяется чтением кода и тестом.
- [ ] Имена, попавшие в стоп-лист общих слов, не порождают находок (иначе гейт станет шумом и его выключат).
- [ ] Второго парсера unified diff в кодовой базе не появилось: `diffLines` одна.
- [ ] Гейт уважает `signal` и укладывается в `timeoutMs`; по таймауту даёт `⏭` с честной формулировкой, а не зависает.
- [ ] Гейт не входит в `MINIMUM` и его выключение закрывается строкой таблицы «Долг» по общим правилам.

## Риски и инварианты
- Ложноположительные срабатывания — главный риск: гейт, который шумит, «приучает игнорировать себя» (шапка `builtin/index.ts`). Поэтому исход `⏭`, требующий подписи, а не `❌`.
- Поиск по чужому дереву — это чтение файлов целевого проекта. Если он реализуется командой (`grep`/`rg`), она идёт через `runShell` → `checkBash`, и ввод из diff'а обязан быть экранирован: имена из diff'а приходят от модели. Правило CLAUDE.md про `shellRedirects.ts` («не заменяй лексер регуляркой») отражает ровно этот класс — метасимволы в командах ломались в обе стороны. Предпочтительнее чтение файлов средствами Node, без шелла.
- `\b` в регулярках по кириллице не работает — имена в кодовой базе целевого проекта могут быть не только латиницей.
- `logic.ts` остаётся без файловой системы и git: I/O живёт в `index.ts`.

## Зависимости

остальные поязыковые данные, иначе это ещё один закрытый список.
