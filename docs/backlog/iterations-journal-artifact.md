# Журнал итераций как артефакт

**Пункт плана:** 18 · **Категория:** наблюдаемость
**Слаг витка:** iterations-journal-artifact

## Зачем

Сегодня история попыток chunk↔verify не собрана нигде в одном месте. Она размазана
по трём источникам, и ни один не отвечает на вопрос «почему витку понадобилось четыре
попытки»:

- `chunk-<n>-attempt-<k>-diff.patch` и `verification-report-<n>-attempt-<k>.md`
  (`server/src/artifacts/paths.ts`) — есть по одному файлу на попытку, но чтобы собрать
  из них картину, человек должен открыть их все и сравнить руками;
- `Run.verdict` и `Run.lastGateResults` (`server/src/run/Run.ts`) сбрасываются в
  `resetAttemptState()` при переходе к новой попытке — это правильно (иначе интерфейс
  рисовал бы зелёный вердикт прошлой попытки рядом с номером новой), но значит, что
  причины красного предыдущей попытки после `nextAttempt()` не существуют нигде в памяти;
- шина событий (`server/src/bus.ts`) вытесняет старое с начала буфера, а при перезапуске
  сервиса пропадает целиком — тогда как весь остальной виток переживает перезапуск,
  потому что живёт на диске.

Следствие: промпт ретрая (карточка `retry-with-diagnosis`) не может опереться на «что
уже пробовали и почему не вышло», а `detectNoProgress()` остаётся единственным
механическим сигналом — и он умеет отличить только дословно совпавшие diff'ы.

## Что сделать

1. Завести `iterations.md` как артефакт витка: путь — новый геттер в `WitokPaths`
   (`server/src/artifacts/paths.ts`), файл общий на виток, не на chunk, потому что
   вопрос «сколько итераций съел виток» задаётся к витку.
2. Добавить короткий ключ в `ArtifactKey`/`ARTIFACT_KEYS` и в `artifactPathOf` — иначе
   артефакт не показать и не подписать через `POST /api/runs/:id/decision`. Ключ нужен
   именно потому, что клиент не должен называть произвольный файл на диске.
3. Дописывать строку по факту посчитанного вердикта — в `Run.computeStageVerdict`, рядом
   с `this.emit({ type: 'verdict', … })`: chunk, попытка, `verdict.passed`/`action`,
   `verdict.reasons` дословно, статусы упавших гейтов из `gateResultsForVerdict()`,
   размер diff'а попытки, `noProgress`.
4. Писать строку дописыванием (append), а не перезаписью файла: попытки не
   перезаписываются нигде в этом коде по той же причине, по которой не перезаписываются
   их патчи — стёртая улика не восстанавливается.
5. Колонку «что изменилось» заполнять машинно тем, что рантайм видел сам (число файлов и
   строк в diff, разница с предыдущим патчем), а не пересказом модели. Место под
   человеческую заметку оставить отдельной колонкой и не обещать, что оно заполнено.
6. Отдать содержимое наружу: либо новым полем в `RunDetail`, либо как обычный артефакт
   этапа — решить одним способом, а не двумя.

## Файлы

- `server/src/artifacts/paths.ts` — геттер пути `iterations.md`, ключ в `ArtifactKey`,
  ветка в `artifactPathOf`
- `server/src/run/Run.ts` — запись строки в `computeStageVerdict`, чтение при сборке
  промпта ретрая
- `server/src/artifacts/artifact.ts` — при необходимости хелпер дописывания строки
  таблицы (проверить, что подходящего ещё нет, прежде чем писать новый)
- `shared/src/api.ts` — если содержимое отдаётся полем `RunDetail`

## Приёмочный лист

- [ ] После двух подряд красных попыток `iterations.md` содержит две строки, и обе
      называют причины дословно из `Verdict.reasons`
- [ ] Перезапуск сервиса между попытками не теряет уже записанные строки
- [ ] `nextAttempt()`/`nextChunk()` не стирают и не переписывают ранее записанное
- [ ] Запись происходит и при `passed=true` — зелёная попытка это тоже итог итерации
- [ ] Клиент не может записать в `iterations.md` произвольного витка: путь собирается
      рантаймом по ключу
- [ ] Файл читается человеком как таблица: колонки не разъезжаются на причине с `|`
      внутри (см. экранирование в `gateReportBlock`)

## Риски и инварианты

- **Артефакт методологии или служебный файл рантайма?** `.sdlc/<slug>/` читают и скиллы
  `/sdlc-*` — имя без точки в начале обещает канонический формат. Либо согласовать форму
  с эталоном методологии, либо назвать файл служебным по образцу `.chunk-N-baseline.json`.
- `pathScope` открывает каталоги методологии только на чтение, а исключение `planScope`
  для `.sdlc` сужено до своего витка. Новый артефакт обязан попасть ровно под это
  исключение и не расширять права записи.
- Дописывание в файл из `computeStageVerdict` — это I/O в функции, которая сегодня
  считает вердикт. Вердикт (`verdict/verdict.ts`) обязан остаться чистым: писать из
  `Run`, а не из него.
- Не делать `iterations.md` входом рецензента этапа 6: методология перечисляет его входы
  исчерпывающе (задача, план, набор гейтов, diff) и журнал исполнителя туда не входит
  намеренно — см. комментарий к `stageInputs` в `server/src/run/stages.ts`.

## Зависимости

Нет. Карточки `retry-with-diagnosis` и `postmortem-iteration-report` читают этот
артефакт — их лучше делать после.
