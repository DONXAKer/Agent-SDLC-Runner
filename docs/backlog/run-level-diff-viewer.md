# Diff-вьюер уровня витка

**Пункт плана:** 28 · **Категория:** UI/UX оператора
**Слаг витка:** run-level-diff-viewer

## Зачем

`web/src/components/DiffView.tsx` работает ровно с одним вызовом: он принимает
`before`/`after` одного файла и рисует построчное сравнение по LCS. Его источник —
`PendingApproval.preview` (`shared/src/api.ts`), который строится в
`server/src/approval/preview.ts` **после** разрешения политики, для одного вызова
записи, и живёт ровно до ответа оператора.

Сводного взгляда на накопленную работу в интерфейсе нет вовсе. Всё, что видит оператор
после десятка одобрений, — исчезнувшие карточки в ленте. Между тем накопленный diff
существует на диске: `chunk-N-attempt-K-diff.patch` (`server/src/artifacts/paths.ts`),
и именно он — вход рецензента этапа 6 и вход scope-гейта. То есть человек одобряет
запись за записью, а суммарный результат впервые видит только глазами рецензента, в
пересказе отчёта.

Отдельно не видно самого дорогого признака — файлов **вне** плана. `planScope`
(`server/src/policy/planScope.ts`) запись вне `files_to_touch` не пропускает, и
встроенный гейт `scope: файлы вне плана` считает это на этапе 6. Но между «политика
отклонила» и «гейт покраснел» у оператора нет ни одной поверхности, где список
затронутых файлов сопоставлен с планом.

## Что сделать

1. Компонент сводного просмотра: список затронутых файлов + просмотр diff'а выбранного.
   Источник — патч попытки на диске; отдавать его отдельной ручкой, а не полем
   `RunDetail` (патч бывает в сотни килобайт, а `RunDetail` перезапрашивается на каждый
   `artifact_written`).
2. Группировать файлы по `plan.files_to_touch`: в плане — вне плана. Список брать через
   `extractFilesToTouch` (`server/src/artifacts/planFiles.ts`), а не разбирать план в
   вебе второй раз.
3. Файлы вне плана подсвечивать и называть причину: запись туда либо не проходит
   политику, либо (если файл изменён не агентом) вменяется исполнителю scope-гейтом —
   для этого и снимается baseline `chunk-N-baseline.json`.
4. Переиспользовать `DiffView` для показа одного файла, а разбор unified diff'а патча в
   пары «до/после» — вынести отдельно и не смешивать с LCS-алгоритмом.
5. Не считать LCS на всём патче разом. В `DiffView` уже стоит потолок `MAX_LCS_CELLS`
   именно потому, что квадратичный алгоритм вешает вкладку на сгенерированном файле;
   для готового unified diff'а LCS вообще не нужен — там уже есть `+`/`-`.
6. Дать выбор попытки, если панель попыток (`attempts-panel`) уже есть: патчи попыток не
   перезаписываются намеренно, и сравнение двух подряд — то, ради чего они хранятся.

## Файлы

- `web/src/components/DiffView.tsx` — переиспользовать как есть для одного файла
- `web/src/components/RunDiff.tsx` — новый компонент сводного просмотра
- `web/src/pages/RunPage.tsx` — размещение (правая колонка рядом с `GatePanel`, либо
  отдельная секция)
- `web/src/lib/api.ts` — вызов ручки патча
- `server/src/index.ts` — ручка отдачи патча попытки
- `server/src/artifacts/paths.ts` / `planFiles.ts` — путь патча и список файлов плана

## Приёмочный лист

- [ ] После этапа 5 виден список всех файлов патча попытки, а не только последний
      одобренный вызов
- [ ] Файлы вне `files_to_touch` визуально отделены и подписаны причиной
- [ ] Патч на несколько тысяч строк открывается без зависания вкладки
- [ ] Отсутствующий патч (этап 5 ещё не шёл) даёт понятное «нечего показывать», а не
      пустой экран и не ошибку
- [ ] Ручка отдаёт патч только текущего витка: путь собирается рантаймом по
      chunk/attempt, а не приходит от клиента
- [ ] Ошибка запроса патча показывает состояние ошибки, а не выглядит как «изменений нет»

## Риски и инварианты

- Новая ручка чтения файла — новая поверхность. Имена артефактов превращаются в пути
  **только** в `server/src/artifacts/paths.ts`; клиент называет chunk и попытку числами,
  путь собирает сервер. Иначе это чтение произвольного файла с диска.
- Просмотр — не одобрение. Гейт одобрения записи остаётся там же, где был, и сводный
  вьюер ничего не разрешает.
- `preview` для одного вызова строится только после разрешения политики — этот порядок
  трогать нельзя (отклонённый `Write ~/.ssh/id_rsa` иначе успевал прочитать файл и
  разослать его в шину). Сводный вьюер читает патч, уже лежащий в `.sdlc/<slug>/`, и в
  этот порядок не вмешивается.
- Патч может быть большим: не класть его в `RunDetail` и не гонять по WebSocket.

## Зависимости

Нет обязательных. Выигрывает от `attempts-panel` (выбор попытки) и полезен ей взамен
(переход «попытка → diff»).
