# Бэклог: 30 улучшений Agent-SDLC Runner

Разбор продукта как системы: качество выполнения задачи за приемлемое число итераций,
поддержка разных языков и паттернов, UX самого витка. Тридцать пунктов; по четырём код
написан (но не прогонялся), по остальным двадцати шести здесь лежат карточки.

Карточка — вход в `/sdlc-intent`: имя файла и есть слаг витка. Внутри — зачем (со ссылкой
на конкретный файл и на то, чем сегодняшнее положение оборачивается), что сделать, какие
файлы, приёмочный лист, риски и задетые инварианты, зависимости.

## Написано, но на живом витке не прогонялось

Код этих четырёх пунктов есть в дереве и проходит `typecheck`, но ни одна из функций ни
разу не выполнялась в браузере на реальном витке — как и сквозной виток целиком (см.
раздел «Состояние» в `CLAUDE.md`). Считать пункты закрытыми до прогона нельзя.

| Пункт | Что | Где |
| --- | --- | --- |
| 22 | Список открытых витков: возврат в прогон, из которого вышел | `web/src/components/RunList.tsx` |
| 23 | Отмена прогона из интерфейса (подтверждение вторым кликом) | `web/src/pages/RunPage.tsx` |
| 24 | Сводная таблица гейтов вместо поиска в хронологической ленте | `web/src/components/GatePanel.tsx` |
| 30 | Счётчик ожидания в заголовке вкладки и системное уведомление | `web/src/lib/useOperatorAlerts.ts` |

Список витков — это витки из памяти сервера, а не история на диске: после перезапуска
сервера он пуст, хотя `.sdlc/<slug>/` целевого проекта цел. История на диске сервером не
читается вовсе — это работа из карточки `run-metrics`.

## Порядок, который я бы взял

1. `retry-with-diagnosis` — данные собраны, транспорт написан, недостаёт сборки текста и
   одного вызова. Прямое попадание в цель «меньше итераций».
2. `red-cause-classifier` и `progress-by-diff-distance` — поверх неё.
3. Связка реестра экосистем (1, 2, 3, 5) — она разблокирует всю мультиязычность.
4. `iterations-journal-artifact` + `run-metrics` — без них улучшения нечем мерить.
5. `loop-subagents` и `seed-calibration-loop` — долгие, но замыкают заявленные дыры.
