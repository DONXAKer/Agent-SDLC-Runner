# Журнал прогонов моделей

Что каждая модель делает на живом витке — измерением, а не впечатлением. Файл **дописывается**:
строки не переписываются и не удаляются, потому что смысл журнала в том, чтобы следующий человек
не повторял уже поставленный опыт. Прогон, чей результат позже опровергнут, остаётся на месте —
рядом дописывается новая строка с причиной.

## Как ставить опыт

Одна задача, один этап, меняется только модель. Иначе сравнивать нечего: смена задачи и модели
разом даёт «стало хуже» без ответа на вопрос, от чего.

```bash
# 1. Раннер (LM Studio слушает свой порт — смотри `lms server start`, он его печатает)
LMSTUDIO_BASE_URL=http://localhost:1434/v1 npm run start --workspace server

# 2. Прогон с точечной подменой модели одного этапа
curl -s -X POST http://127.0.0.1:8030/api/runs -H 'content-type: application/json' \
  -d '{"project":"…","slug":"проба-модели","profile":"local","stages":{"intent":"ollama:…"}}'

# 3. Числа — из ответа GET /api/runs/:id (metrics.friction, usage) и из
#    .sdlc/<slug>/.events.ndjson целевого проекта
```

Что записывать обязательно: **во что упёрлись**. «Не справилась» — не наблюдение; наблюдение —
«окно 4096, сумма вход+выход упёрлась в него ровно», «12 ГБ при 8 ГБ VRAM», «14 вызовов Bash,
артефакта нет».

## Прогон 2026-08-28 · этап 1 (цель витка) · проект WarCard

Задача-пустышка: пересчитать `status: planned` в `tasks/active/` и записать число в артефакт.
Машина: 8 ГБ VRAM, 48 ГБ RAM. Этап обязан произвести `intent.md` и `readiness.md`; пока их нет,
следующие этапы заблокированы.

| `qwen3.5:4b-ctx16k` | ollama | ход завершён, артефакта нет | 30 с | 46 956 / 1307 | 5 вызовов на чтение, два — в каталог методологии вместо проекта |
| `qwen2.5:14b-ctx16k` | ollama | обрыв | 303 с | 0 / 0 | **не модель**: таймаут HTTP-клиента (см. ниже) |
| `qwen3.5:9b-ctx16k` | ollama | ход завершён, артефакта нет | ~4 мин | 23 395 / 2287 | провела интервью из 4 вопросов, форму прочитала, записать не смогла |
| `qwen/qwen3.5-9b` | LM Studio | ход завершён, артефакта нет | ~2 мин | 32 127 / 1087 | пошла копировать шаблон в проект через `Bash`; после отказа завершила ход |

### Что из этого следует

- **Окно контекста задаётся тегом, а не конфигом.** У ollama «голый» тег даёт 4096; провайдер
  `num_ctx` не шлёт, потому что у OpenAI-совместимого API такого поля нет. В профилях только
  производные с зашитым окном (`-ctx16k`). У LM Studio то же самое задаётся при загрузке:
  `lms load <model> -c 16384 --gpu max`.
- **Записать артефакт по форме — тот шаг, который локальным не даётся.** 4B, 9B (обе среды) и
  35B-дистиллят дошли до чтения шаблона и не записали ничего. Различался только способ не
  справиться: 9B ollama спрашивала человека, 9B LM Studio и 35B шли в `Bash`.
- **`Bash` — ловушка для локальных.** Модель, которой доступна оболочка, начинает решать задачу
  копированием файлов и перебором команд. На этапах, где нужен артефакт, право `Bash` стоит
  снимать, а не полагаться на просьбу в промпте.
- **Контроль обязателен.** Без прогона на сильной модели вывод «локальные не тянут» неотличим от
  «раннер сломан»: `intent.md` от haiku появился на той же машине и том же промпте.

### Найденный дефект: 300 секунд — это был наш таймаут

14B через ollama и 35B через LM Studio умерли на **303.7 с** и **303.9 с** с `fetch failed` —
разные серверы, разные модели, одна цифра. Это потолок ожидания заголовков у встроенного
`fetch` (undici, 300 с), который не настраивается из `RequestInit`: ответ мы просим не потоковый,
поэтому заголовки приходят только с готовым ответом, и любая генерация дольше пяти минут
обрывалась независимо от `chatTimeoutMs: 600000`.

Выглядело как «железо не тянет 14B». После замены транспорта на `node:http`
(`OpenAiCompatProvider.postJson`) 35B-дистиллят отработал больше десяти минут и пятнадцать ходов.
**Вывод про 14B из строки таблицы считать неустановленным** — модель надо перемерить.

### Не проверено

Этапы 5 и 6 (правка кода и независимый рецензент), `qwen2.5-coder:7b-ctx16k` в роли исполнителя,
14B после починки транспорта, MCP-инструменты (редактор был выключен). Это следующие опыты.

## Прогон 2026-08-28 (после правок) · этап 1 · проект WarCard

Те же задача и машина. Изменилось не в моделях, а в раннере: формы раскладываются до этапа,
`Bash` снят с этапов 1 и 4, «ход завершён» проверяется диском, потолок результата инструмента
для локального контура — 12 КБ.

| Модель | Итог | Что изменилось по сравнению с первым прогоном |
|---|---|---|
| `qwen3.5:9b-ctx16k` (ollama) | этап не пройден, но **честно** | три круга вопросов ПО ПОЛЯМ бланка («Зачем», «Что делаем», «Чего не делаем», пункт приёмки) вместо четырёх общих; заполнить бланк всё равно не смогла; страж дал два замечания и уронил этап с названной причиной |

Что это значит:

- **Форма бланка меняет поведение модели.** До правок 9B спрашивала про устройство витка
  вообще; после — про конкретные поля документа, который у неё перед глазами. Это шаг в
  нужную сторону, но одного его мало.
- **Тихий успех закрыт.** Раньше тот же исход выглядел как «модель завершила ход» + зелёный
  статус + пустой каталог. Теперь: «артефакт этапа не заполнен: intent.md, readiness.md» и
  красный этап. Диагноз стал верным, даже когда результат прежний.
- **Ловушка, найденная на первом же прогоне после раскладки:** проверка «файла нет» стала
  бессмысленной, потому что файл кладёт сам рантайм. Признак теперь точный — бланк,
  оставшийся байт в байт равным форме, работой не считается.

### Не проверено (обновлено)

Этапы 5 и 6, `qwen2.5-coder:7b-ctx16k` как исполнитель, 14B после починки транспорта,
35B-дистиллят после снятия `Bash` (он утонул именно в оболочке — вероятно, теперь исход
другой), MCP-инструменты.
