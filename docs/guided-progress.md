# Guided: устойчивый прогресс и проверяемые предложения

## Принцип

Модель предлагает содержание небольшого шага. Рантайм хранит предложение, проверяет
формат и актуальность источников, выполняет разрешённое действие и записывает результат
наблюдения. Валидный JSON сам по себе не доказывает правильность решения.

Семь пользовательских этапов сохранены. Для новых витков можно явно выбрать движок:

| Версия | Поведение |
| --- | --- |
| 1 | Прежний guided, значение по умолчанию и для старых сохранений |
| 2 | Сохранение структурированных единиц, повторное использование и адресное восстановление |
| 3 | Версия 2; предварительное самоподтверждение модели заменено проверкой предусловий рантаймом |

Версия фиксируется при создании guided-витка. Менять её у существующего витка нельзя.
Она независима от версии форм `preparationVersion`.

```powershell
node bench/src/cli.ts --all --model ollama:gpt-oss-20b-compactfill --task add-validator --execution-mode guided --guided-engine-version 3 --preparation-version 3 --strict-questions
```

API запуска принимает `executionMode: "guided", guidedEngineVersion: 3` на первом этапе.
Дальнейшие этапы используют сохранённую версию. Новый движок остаётся экспериментальным
до измеримого улучшения на повторных полных прогонах и независимой выборке задач.

## Состояние

`.sdlc/<slug>/.runner/progress.json` содержит единицы с зависимостями, ревизией и статусом:

- `proposed`: разобранное предложение модели; смысл ещё требует проверок.
- `observed`: результат проверки кода или полученный ответ человека, записанный рантаймом.
- `stale`: источник или зависимая единица изменились.

Сохраняются исследования отдельных файлов, структурированные значения полей, кандидат
плана и его шаги, вопросы, результаты проверок групп реализации. После прерывания
повторно используются предложения с совпадающими зависимостями; обычные проверки и
политика записи выполняются снова. Независимые единицы исследования сохраняются при
изменении соседнего файла. Ответ с устаревшими источниками не перезаписывает новое состояние.

Markdown остаётся пользовательским представлением и совместимым входом существующей
методологии. При внешнем редактировании документы снова разбираются и зависимости
пересчитываются. Преобразование всей методологии в полностью независимый от Markdown
граф ещё не выполнено: группы реализации по-прежнему консервативно зависят от общей
ревизии плана. Это может вызвать лишнюю работу, но не разрешает переиспользовать
проверку для изменившихся требований.

В `guided.progress` и событиях `guided_progress` доступны состояния единиц, количество
повторных использований и причины остановок. Проверяющему закрыт доступ к журналу
предложений, как и к авторскому архиву flow.

## Восстановление

Для исследования и полей учитываются ошибки одной единицы при одинаковых входах:
две адресные коррекции, затем одна суженная попытка, затем остановка. Смена формулировки
ошибки не обнуляет счётчик. В исследовании сужение ограничивает JSON ошибочными полями
и сохраняет корректных соседей; в формах единица уже ограничена отдельным полем и
получает его конкретную диагностику. Ограничения запросов и отмена имеют приоритет.

Вторичные предложения проверки и ремонта контракта используют тот же сохраняемый
предел; контекст суженного ремонта переживает обрыв провайдера. План восстанавливается
из структурированного кандидата и сохраняет предел адресного ремонта между запусками.
Группы реализации используют сохранённые транзакции,
проверки актуальности и ограниченный ремонт операций. Проверки области изменений,
источников, требований, независимое ревью и итоговые проверки продолжают действовать.

## Измерение

Исходная серия: `bench/results/guided-recovery-20261011191731625/index.html` —
0 из 6 завершённых задач, 41 запрос к моделям, одна зафиксированная версия исходников.
Изолированные `diagnose`-кейсы теперь явно помечаются как legacy/preparation 1 и не
считаются доказательством поведения guided.

`tools/compare-guided.mjs` без `--run` показывает матрицу. С `--run` выполняет её
последовательно, сохраняет команды, отпечаток исходников/конфигурации/фикстур, результаты,
время, токены и ссылки на flow. Изменение отпечатка прерывает сравнение.

```powershell
node tools/compare-guided.mjs --phase progress --run
node tools/compare-guided.mjs --phase comparison --run
node tools/compare-guided.mjs --phase comparison --run --resume bench/results/<series>
node tools/compare-guided.mjs --phase holdout --comparison bench/results/<series>/suite.json --run
```

- `progress`: 2 задачи × модели из `compare-guided.mjs`, движок 2, один повтор.
- `comparison`: 2 задачи × 4 модели (gpt-oss, ministral, qwen, mellum2-q6 compactfill) × 3 повтора × движки 1 и 3 = 48 прогонов.
- `holdout`: другие 2 задачи, та же парная матрица. Разрешён только после улучшения
  полного успеха без ложных успехов и нарушений области изменений в сравнительной серии.

Успех требует handoff, положительного verdict и прохождения всех скрытых проверок.
Прерывание, отсутствие результата и несопоставимая конфигурация отмечаются отдельно.
Промежуточный зелёный этап не считается решённой задачей.
