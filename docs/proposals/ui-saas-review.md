# UI-обзор: перегрузка интерфейса и предложения по редизайну под SaaS-паттерны

Дата: 2026-09-07. Материал: скриншоты реального рендера (StartPage, RunPage, drawer'ы,
узкая ширина) + код `web/src`. Снимки «до»: `bench/.tmp/ui-review/*.png`, снимки «после»:
`bench/.tmp/ui-review/after/*.png` (временные, не коммитятся).

**Статус: quick wins 1–8 и структурный переход на режимы «Сейчас»/«Наблюдение»
реализованы 2026-09-07** (`web`: typecheck чисто, 91/91 тестов; визуально сверено по
скриншотам «после»). Остаток из находок: рельс ниже ~768px не убран в шторку (узкий
экран рабочий, но рельс занимает больше половины ширины) и сайдбар навигации
приложения уровня StartPage не делался.

## Диагноз

Главная проблема не в количестве элементов, а в том, что **три разных намерения оператора
сидят в одной зоне внимания**: «что мне нажать сейчас», «что происходит/случилось» и
«где лежат детали (пути, артефакты, причины блокировок)». Вторичный источник перегрузки —
необработанные машинные данные (абсолютные пути, простыни предусловий) показываются
человеку как есть.

## Находки RunPage (главный экран — главная боль)

### 1. Рельс этапов — самый шумный элемент экрана при самой низкой ценности
- **Что вижу:** 7 этапов, под каждым — многострочный текст блокировок с полными
  абсолютными путями (`— нет файла D:\Проекты\Agent-SDLC-Runner\bench\snapshots\oversize-plan\.sdlc\ui-review\intent.md`),
  переносящимися по 4–6 строк каждый. Левая треть экрана — стена серого текста.
- **Почему боль:** рельс должен отвечать на вопрос «какой этап и в каком он состоянии»
  одним взглядом. Вместо этого оператор читает простыни, 90% которых — пути.
- **Улучшение:** рельс → компактный степпер: номер, название, точка статуса
  (пройден/идёт/доступен/заблокирован) и счётчик «N предусловий». Детали — по клику
  или ховеру, одним сворачиваемым блоком под активным этапом. Пути — относительные
  (от projectRoot), моноширинные, с усечением и копированием по клику.

### 2. Центр экрана — дыра, при этом управление «запихано» наверх
- **Что вижу:** рабочая колонка занимает верхние ~15% высоты, остальное — пустота.
  Одновременно очередь решений, секция промпта, автоодобрение и «Продвижение витка»
  теснятся друг у друга.
- **Почему боль:** визуальный вес распределён наоборот — пусто там, где происходит работа,
  плотно там, где нужен фокус.
- **Улучшение:** экран «Сейчас» как единственная центральная колонна: сверху — одна
  карточка «текущее действие» (решить N запросов / запустить этап X / ждать), ниже —
  её детали на всю ширину и высоту. Пустые состояния («промпт не собран» и т.п.) —
  компактной строкой внутри карточки, а не отдельными панелями.

### 3. Два конкурирующих янтарных баннера об одном и том же
- **Что вижу:** при открытом drawer'е и висящих решениях одновременно показаны баннер
  «Ждут решения — 1» в центре и «Ждут решения — закрыть панель» поверх drawer'а.
- **Почему боль:** дублирующийся сигнал разной формулировки читается как два разных события.
- **Улучшение:** один счётчик-пилюля «Ждут решений: N» (липкий, в шапке), клик — закрывает
  любую панель и скроллит к очереди. Баннер внутри drawer'а убрать.

### 4. Drawer'ы поверх полупрозрачной подложки, контент под ними обрезан
- **Что вижу:** карточка решения под drawer'ом диффа обрезана по краю («следующий э...»);
  снимок fullPage показывает «решётку» экрана.
- **Улучшение:** drawer фиксированной ширины с читаемой подложкой (bg-black/80) ИЛИ переход на полноценные вкладки (см. структурное №1) — тогда проблема исчезает сама.

### 5. «Метрики» — полноэкранная поверхность ради трёх пустых состояний
- **Что вижу:** «Ни один этап ещё не запускался. Вердиктов ещё не было. Попыток ещё не было.»
- **Улучшение:** метрики — вкладка, а не drawer; пустые секции сворачивать до одной строки
  или прятать целиком. Сюда же убрать токены/стоимость из шапки — они наблюдательские.

### 6. Шапка — всё одним весом
- **Что вижу:** slug, полный путь проекта, бейдж статуса, профиль, chunk/attempt,
  токены, стоимость, статус WS — в одну строку, мелко, без иерархии.
- **Улучшение:** хлебные крошки «проект / виток» слева; статус — одна цветная пилюля;
  всё наблюдательное (токены, кэш, $) — в «Метрики». Путь проекта — title по ховеру.

### 7. Узкая ширина (~420px) — не «мобильная версия», а сломанная
- **Что вижу:** рельс съедает ~45% ширины и продолжает показывать стену путей; центр —
  вертикальная полоса; шапка перемазана; легенда внизу нечитаема.
- **Улучшение:** ниже ~768px рельс убирать в сворачиваемую шторку (бургер), центр — 100%.
  Это же упростит и широкий экран: один паттерн «шторка» вместо двух компоновок.

### 8. Чекбоксы автоодобрения в строке с «Собрать промпт»
- **Что вижу:** «одобрить без вопроса: □ правки □ bash □ MCP □ остальное» — четыре опции
  рядом с главной кнопкой этапа.
- **Улучшение:** автоодобрение — раскрываемый блок «безопасный автопилот» под кнопкой
  запуска, с пояснением «сбрасывается по концу этапа». Подписи короче.

## Находки StartPage

1. **Приложение — колонка 672px в центре 1600px.** Для SaaS-ощущения нужен либо
   левый сайдбар (Витки / История / Проекты), либо хотя бы max-w-4xl/5xl и двухколоночная
   сетка «открытое слева, история справа». Сейчас экран выглядит «прототипом»,
   а не продуктом.
2. **Серая простыня микротекста под списком витков** («Это витки, живущие в памяти
   сервера…») — внутреннее объяснение устройства вместо UI. Вынести в «?» рядом
   с заголовком секции.
3. **Мастер: сетка проектов не резиновая** — на узком экране карточки уезжают за край
   (снимок 06: переполнение по горизонтали). `grid-cols-2` → `grid-cols-1 sm:grid-cols-2`.
   Полные пути проектов — снова в лоб; усечение + title.

## Структурное предложение (чтобы «как SaaS»)

Разнести три режима по маршрутам, а не по панелям одного экрана:

- `#/runs` — список живых витков + история (что уже есть на StartPage, плюс сайдбар).
- `#/runs/:id/now` — управление: очередь решений, текущее действие, запуск этапа.
  Никаких путей и лент — только то, что требует руки оператора.
- `#/runs/:id/observations` (вкладки: Лента · Дифф · Метрики · Артефакты) — наблюдение.
  Вкладки вместо drawer'ов убирают баннер-дубль, обрезание под подложкой и борьбу
  панелей за место.
- Рельс этапов остаётся на `now` компактным степпером; на observations — фильтром
  «показать события этапа N».

## Quick wins (без смены архитектуры)

1. Пути везде → относительные + truncation (рельс, артефакты, заголовок).
2. Блокировки в рельсе → счётчик с раскрытием по клику.
3. Один баннер «Ждут решений» вместо двух.
4. Токены/$ из шапки → в «Метрики»; шапка → крошки + статус-пилюля.
5. Чекбоксы автоодобрения → сворачиваемый блок.
6. Пустые состояния метрик → одна строка вместо трёх секций.
7. Мастер: резиновая сетка, усечение путей.
8. Контентную колонку StartPage расширить до max-w-4xl+.

## Что оставить

- Мастер «Новый виток» — правильное решение, продолжать в том же духе.
- DecisionQueue всегда развёрнут — «молчание одобрением не считается».
- Вердикт в центре на verify — главный вход решения, не прятать.
- Логика фокуса (`computeNowFocus`) — готовый механизм для экрана «Сейчас».
