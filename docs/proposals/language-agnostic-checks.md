# Проверки без привязки к языку: что ломает модели и как это закрыть конструкцией

Основание — разбор `docs/model-task-matrix.md` (2026-09-11) под требование: **проекты
будут на разных языках и технологиях, завязываться на один язык нельзя**. Документ
фиксирует три вещи: (1) какие отказы матрицы вообще не про язык и лечатся общей
конструкцией; (2) что в раннере уже языко-нейтрально, а где осталась TS-специфика;
(3) что ещё ломает модели при написании проверки — и почему честный ответ на это
языко-нейтральный по построению (посев, а не парсинг).

Связанные документы: классы отказа и их лекарства — `docs/weak-models-analysis.md`;
порядок «корпус → ручки → маршрут → веса» — `docs/model-tuning.md`. Здесь — только
срез «проверки × многоязычие».

## 1. Главное наблюдение: большинство отказов матрицы не про язык

Перечитывание матрицы под углом «что из этого зависит от языка целевого проекта» даёт
неожиданно короткий список. **Не** зависят от языка и лечатся общей конструкцией:

| Класс отказа (по матрице) | Кто | Лекарство |
|---|---|---|
| Лимит длины ответа / переполнение контекста | `agents-a1-4b`, `omnicoder-9b` (4–5 подтверждений), `qwen3.8-27b`, `glm-4.7-flash*` | бюджет окна рантаймом, `formFill`/`stepFill` |
| Краш движка LM Studio | `glm-4.7-flash-zaiorg`, `deepseek-r1-0528-qwen3-8b`, `gemma-4-12b` | health-check и автоперезагрузка движка — обвязка провайдера |
| Застревание без `FinalizeArtifact` / нераспознанная завершённость хода | `qwen3-coder-30b` (ghost-requirement, ask) | детектор застревания шире «серии отказов» |
| `Edit` многострочных блоков портит файл | три разных класса порчи за обе ночи | `stepFill` (блоки `SEARCH/REPLACE` — нейтральны по построению) |
| План с пустым списком файлов; числа плана не в diff'е | `ministral-14b` (security-bait), `gemma-4-e4b` | гейты формы плана до старта chunk |

Зависят от языка ровно два класса, и оба — из этапа 5:

1. **Формат пути импорта** (`./money` vs `./money.ts`, `../tariffs` vs `../src/tariffs.ts`,
   `.js` vs `.ts`) — три модели независимо, 2026-09-10. Сейчас ловится только для TS.
2. **Символ не связан** (`ReferenceError: add is not defined`) — виден только при
   исполнении, не при разборе модуля.

Оба класса — частные случаи одного общего: **правка прошла проверку синтаксиса, но не
проверку связанности**. Именно эту пару и надо закрывать пер-экосистемно.

## 2. Инвентарь: что уже нейтрально, где осталась TS-специфика

### Уже нейтрально

- **Контракт проверок — командой проекта.** `.sdlc/gates.md` несёт команду в обратных
  кавычках (`make`, `pytest`, `npm test`); разбор `parseCommand`
  (`server/src/gates/gatesFile.ts:122`) принимает любую. Приоритет источников: команда
  проекта > описание модуля в конфиге > автодетект (`resolveCommands`,
  `server/src/gates/builtin/index.ts:312`).
- **Реестр экосистем** (`server/src/gates/ecosystems/`): node, python, go, jvm, rust,
  php, ruby, dotnet, swift — у каждой свои команды сборки/теста, линтер, чекер
  синтаксиса, каталог зависимостей. Запасная ветка `syntaxOnly` уже выбирает чекер по
  расширению через `syntaxCheckerFor`, а не только по `.js`.
- **Проверка после шага в `stepFill`** — уже «Сборка» + «Тесты» безусловно
  (`gatesForStep`, `server/src/run/stages/chunk/steps.ts`; команда берётся из того же источника,
  что гейты этапа 6, значит нейтральна). Запись «тесты гоняются после этапа, не после
  шага» из `docs/weak-models-analysis.md` **устарела** — сужение по тестовым файлам
  снято после живого замера трёх моделей (та же дока `gatesForStep`).
- **Честная деградация**: где инструмента нет — `⏭` с названной причиной, а не зелёный
  («гейт, который врёт, приучает игнорировать себя», `gates/builtin/index.ts`). Это и
  есть языко-нейтральная дисциплина: незнакомый язык не должен зеленеть.
- **`stepFill`/`formFill` нейтральны по построению** — ни блоки `SEARCH/REPLACE`, ни
  карточки полей о языке не знают.

### TS-специфика, которая осталась

- **Гейт «Импорты»** (`server/src/gates/builtin/imports.ts` + `server/src/fs/tsSpecifier.ts`):
  регекс `import ... from` и достройка `.ts`/`.tsx`/`index.ts`. Дока самого гейта это
  признаёт честно: «формат пути специфичен для конкретного целевого проекта, и решает
  его проект через `.sdlc/gates.md`, не раннер безусловно для всех». Опт-ин уже есть
  (`gatesForStep` берёт строку, только если проект сам её завёл) — не хватает
  пер-экосистемных реализаций.

## 3. Предложение: связанность как хук экосистемы, а не универсальный парсер

Раннеру нельзя знать синтаксис языков. Ему нужно знать **три вещи на модуль**: собрать,
прогнать тесты, проверить связанность. Первые две уже нейтральны; третья оформляется
тем же приёмом, что линтер:

1. В `server/src/gates/ecosystems/types.ts` — опциональный хук экосистемы
   `linkageCheck(changedFiles)` рядом с существующими `lint`/`syntaxCheck`. Реализации
   по экосистеме, минимальный набор:
   - python — импортируемость модуля по `sys.path` проекта (`python -c "import …"` на
     изменённый модуль), не только `compile()`;
   - go — `go build ./...`/`go vet` на затронутом пакете;
   - rust — `cargo check`;
   - jvm — компиляция модуля (уже есть как `build`);
   - ruby/php — текущий синтаксис-чекер (связанности нет — честный `⏭`);
   - node/ts — существующий `imports.ts` переезжает под этот хук без изменения семантики.
2. Где хука нет или инструмента нет на машине — `⏭` с формулировкой «связанность НЕ
   проверялась», по действующему правилу честной деградации. Никакого «зелёного по
   молчанию» для незнакомого языка.
3. Гейт «Импорты» остаётся опт-ином проекта (текущее поведение `gatesForStep`
   сохраняется) — раннер не навязывает языковую проверку всем.

Граница, которую важно не перейти: хук — это **вызов инструмента экосистемы**, а не
свой парсер языка в раннере. Урок уже оплачен: регекс в `imports.ts` сначала молчал на
дефолтных/namespace-импортах, и чинить его пришлось живым замером; умножать этот класс
поддержки на девять языков — прямой путь к вечному отставанию от синтаксиса.

## 4. Что ещё ломает модели при написании проверки — и нейтральные ответы

Отдельный букет матрицы — этап verify. Его классы ловушек почти все нейтральны сами по
себе, и нейтральны их лекарства:

| Класс (матрица) | Пример | Нейтральное лекарство |
|---|---|---|
| Проверка зеленеет, не проверяя код | `gpt-oss-20b`: `NaN == NaN` зеленеет, эскалация по своим тестам | **посев** (`bench/src/seeds.ts` построен, базовая линия НЕ снята): дефект известного класса обязан быть пойман, иначе проверка признана слепой. Универсального линтера «тест ничего не проверяет» не существует ни для одного языка — посев заменяет его целиком |
| Собственный тест модели ломается чаще продукта | `qwen3-coder-30b` ×3, `qwen3:8b` ×2 (`add is not defined`) | собственный тест — тоже артефакт с гейтом: запуск той же командой `test` модуля ДО вердикта; «написан» ≠ «засчитан» |
| «Зелёный, потому что не запустился» | общий вид `NaN==NaN`: 0 собранных тестов = exit 0 у многих раннеров | тот же посев + разбор счётчиков вывода там, где экосистема их даёт |
| Адресация находок врёт | «файл:строка 154», фактически `:158` | находка обязана нести цитату; рантайм сверяет цитату с реальной строкой — текстовая операция, нейтральна |
| Регрессия между попытками | `ministral-14b` затёрла экспорт, добавленный ею же | дифф-гард «то, что проходило, обязано продолжать проходить» — сверка по гейтам, нейтральна |
| Эскалация по своим тестам, а не по коду | `gpt-oss-20b`, verify | вердикт эскалации обязан различать «код плох» и «проверка плоха» — это разные диагнозы с разным продолжением |

Пер-языковые ловушки при написании тестов (на будущие экосистемы, для чек-листа):
python — относительные импорты и `__init__.py`, `pytest` vs `unittest` собирают разное;
go — module path vs локальный путь, `_test.go` в том же пакете; rust — `mod`-объявления,
cargo workspace; jvm — package ↔ каталог, медленные демоны gradle/maven (таймауты
гейта). Общий принцип тот же: раннер вызывает инструмент экосистемы и верит его коду
возврата, а зоркость проверки калибрует посев.

## 5. Следствие для bench: годность не переносится — даже внутри одного языка

`freeship` показал: все пять «годных по `oversize`» моделей встали на `explore`, включая
лучшую (`gemma-4-e4b`). Если задачи одной фикстуры не переносятся, перенос между
языками тем более нельзя предполагать — его надо измерять. Минимальный шаг: по одной
фикстуре-ловушке на экосистему, начиная с python (дешевле всего: шага сборки нет,
ветка `syntaxOnly` уже работает) и go (связанность видна компилятором — самый чистый
замер хука из §3). Без этого «годна» в матрице остаётся заявлением про TS-фикстуры.

Порядок снятия — как в `docs/model-tuning.md`: сперва посев (п. 2 — он мерило для

экосистем (пп. 1, 7). Одна ручка за прогон, серия ≥5, контроль сильной модели в тот же
день.
