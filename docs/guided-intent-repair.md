# Ремонт контракта Intent

Модель возвращает типизированные значения адресованного раздела. Рантайм сохраняет его формат хранения: JSON-маркеры остаются JSON-маркерами, существующие таблицы — таблицами. Весь документ при ремонте не преобразуется. Так многострочный JSON не становится короткой таблицей, ошибочно вызывающей защиту от разрушающей перезаписи. Другие разделы сохраняются побайтово.

Ремонт приёмки и оснований обязан сохранить точный набор ID требований. Процедуры, критерии, сценарии и контрпримеры — обязательные непустые поля. Ссылки сверяются с переданными запросами до любого рендера; хранение в JSON не отменяет проверки цитат. Независимая проверка контракта по-прежнему проверяет исправленный смысл. Структурная валидация не доказывает смысловую эквивалентность произвольного текста.

Записи проходят существующий гейт одобрения с проверками разрушающей перезаписи. После решения гейта рантайм проверяет отмену и сравнивает текущий файл с проверенной версией перед записью. Изменённый, удалённый или нечитаемый документ не перезаписывается.

Трасса различает `JSON ремонта проверен … Запись ещё не выполнена` и `Ремонт записан через гейт` либо `JSON принят, но ремонт не записан`. Последнее событие содержит точную причину отказа записи. Принятый JSON ещё не означает изменения артефакта на диске.

`server/test/guidedRepairGate.test.ts` проверяет публичный исполнитель с фикстурами внешней модели и настоящим гейтом: сохранение формата, потерю ID и критериев, границы цитат, отмену и изменение файла во время одобрения.
