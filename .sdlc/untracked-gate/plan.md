## Подход
Добавить в `server/src/gates/builtin/index.ts` встроенный гейт `untrackedGate` по образцу
соседних `scopeGate`/`planCoverageGate`: использовать уже импортированные в этом файле `git`
и `isRepo` из `../git.ts` (новых импортов не требуется) — `git ls-files --others
--exclude-standard` уже сам исключает игнорируемые `.gitignore`'ом файлы, поэтому claim-4
закрывается без дополнительной логики, а из оставшегося перечня отфильтровать пути под
`.sdlc/`. Зарегистрировать функцию в `BUILTIN` под ключом `scope: нетракованные файлы` — это
имя уже используется в `server/src/verdict/classify.ts:35` и в тесте `classify.test.ts`
(«классифицируется как scope»), то есть регистрация закрывает уже существующий пробел, а не
заводит новую сущность с нуля.

## Шаги
1. В `server/src/gates/builtin/index.ts` реализовать `const untrackedGate: BuiltinGate = ...`
   рядом с `scopeGate`/`planCoverageGate`: не git-репозиторий → `⏭`; иначе — использовать
   `git(['ls-files', '--others', '--exclude-standard', '--', '.'], ctx.projectRoot, ctx.signal)`
   (использовать уже импортированный `git`), отфильтровать пути, начинающиеся с `.sdlc/`; пусто
   → `✅` с числом проверенных; иначе → `❌` с перечнем путей в `lastLine`.
2. Добавить строку `['scope: нетракованные файлы', untrackedGate]` в карту `BUILTIN` (там же,
   `server/src/gates/builtin/index.ts`).
3. Написать `server/test/untracked.test.ts`: реальный git-репозиторий на диске (по образцу
   `server/test/gateHonesty.test.ts` — прямой вызов `BUILTIN.get('scope: нетракованные
   файлы')`, а не `runGates`/`gates.md`, см. отклонение от intent.md ниже), покрывающий
   claim-1 … claim-5.

## files_to_touch
_Пути от корня репозитория. **Не копия** «Что придётся тронуть» из задачи: план вправе сузить или
расширить список, но каждое расхождение объясняется строкой под таблицей — это и проверяет человек.
Пути `.sdlc/**` в список не входят: артефакты процесса из scope-сверки исключены._

| Путь | Что делаем |
|---|---|
| server/src/gates/builtin/index.ts | Добавить функцию `untrackedGate` и зарегистрировать её в `BUILTIN` под ключом `scope: нетракованные файлы` |
| server/test/untracked.test.ts | Новый тест: claim-1…claim-5 через прямой вызов `BUILTIN.get(...)` на реальном git-репозитории |

- **Добавлено сверх разведки:** нет — «Что придётся тронуть» в intent.md было не заполнено
  (контур мелкий, формальной разведки не было); список выше — результат точечной разведки этого
  этапа, полностью совпадает с «Что делаем» из intent.md.
- **Из задачи исключено**: `.sdlc/gates.md` — интент подразумевает существующую строку набора
  «Scope: нетракованные файлы» с реализацией через `git status --porcelain», но по факту такой
  строки в наборе НЕТ вовсе (проверено `grep`). Файл `.sdlc/**` в `files_to_touch` не входит по
  правилу scope-сверки в любом случае, поэтому добавление строки в набор — отдельное решение
  человека вне этого chunk'а, а не пропуск с нашей стороны.

## Затронутые вызовы/сигнатуры
_Для каждого символа, чья сигнатура, контракт или видимое поведение меняется шагом плана — список
его вызывающих (`Grep` по репозиторию, не только по `files_to_touch`)._

н/п — `untrackedGate` новый символ, вызывающих у него ещё нет. Единственная правка существующего
символа — добавление одной записи в литерал карты `BUILTIN: ReadonlyMap<string, BuiltinGate>`;
её тип и контракт (`BuiltinGate`, `builtinFor`) не меняются, дописывание записи не требует правки
вызывающих (`gates/run.ts`, `verdict/classify.ts`, тесты) — они уже читают карту по ключу и уже
ожидают этот ключ (`classify.ts:35`).
