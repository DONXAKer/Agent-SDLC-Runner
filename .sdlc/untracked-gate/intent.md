# Задача: Встроенная реализация гейта «Scope: нетракованные файлы»

> Этап 1. Заполняет **человек**; секцию «Что придётся тронуть» — разведка, ответы в «Открытых
> вопросах» закрывает этап 3. Проверка готовности — SDLC.md методологии Agent-SDLC → этап 1, её результат — в `readiness.md`.

- **Контур:** мелкий — только реализация гейта в файле и его тест, контракты и политику не трогаем
- **Ветка витка:** sdlc/untracked-gate

## Коротко
Завести встроенную реализацию гейта «Scope: нетракованные файлы» и зарегистрировать её в BUILTIN, заменив текущее закрытие через `git status --porcelain`.

## Зачем
Гейт закрывается командой `git status --porcelain`, которая всегда возвращает код 0 независимо от состояния дерева — ложный зелёный по построению. Гейт не может судить о нетрашенных файлах вне плана и превратился в рубиловку статуса.

## Что делаем
- Реализовать встроенный гейт для проверки нетрашенных файлов в `server/src/gates/builtin/index.ts`
- Логика: нетрашенные файлы вне `.sdlc/` роняют гейт с перечнем; всё в `.sdlc/` не считается нарушением; всё, что git игнорирует (`.gitignore`), не считается нарушением; репо, который не git, даёт пропуск
- Зарегистрировать гейт в BUILTIN таблице под именем «Scope: нетракованные файлы»
- Написать тест по образцу `server/test/gateToolMissing.test.ts`, проверяющий обе полярности: красный при нетраке вне `.sdlc/` и зелёный при нетраке только внутри или игнорируемом

## Чего не делаем
- Не меняем контракты GateContext или BuiltinOutcome
- Не трогаем политику в `server/src/policy/`
- Не добавляем новых зависимостей
- Не расширяем scope-гейты, существующие в наборе — только добавляем реализацию под существующей строкой
